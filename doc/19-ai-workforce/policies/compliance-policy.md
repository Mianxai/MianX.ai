# Mianx.ai AI Workforce Compliance Policy

> **This policy defines the governed target-state compliance requirements
> through which Mianx.ai identifies obligations, determines applicability,
> assigns ownership, maps controls, preserves records, produces evidence,
> trains Human and AI Workforce participants, monitors performance,
> assesses conformity, manages findings, remediates deficiencies, controls
> exceptions, responds to violations, and demonstrates bounded compliance
> across the Company, Core Platform, AI Operating System, Shared AI Workforce,
> Industry Operating Systems, Customer Editions, Products, Projects,
> Customers, Tenants, providers, regions, environments, Tools, Models,
> memory systems, Data systems, workflows, Tasks, and Production operations.**

# 3. Strategic Alignment

Compliance must preserve the exact Mianx.ai hierarchy:

```text
Mianx.ai Company and Governance
↓
MianX Core Platform
↓
Mianx.ai AI Operating System
↓
Shared AI Workforce
↓
Industry Operating Systems
↓
Customer Editions
↓
Autonomous Enterprise Creation at Scale
```

Compliance controls must not allow:

- a Customer Edition to override Company Governance;
- an Industry Operating System to override Core Platform controls;
- a Project to redefine Product compliance ownership;
- a Customer request to override applicable obligations;
- one Tenant’s configuration to weaken another Tenant’s controls;
- an Agent to determine legal applicability independently;
- a Tool or Model provider claim to replace Mianx.ai due diligence;
- commercial urgency to bypass mandatory controls;
- a temporary waiver to become permanent silent non-compliance.

# 11. Founder Compliance Authority

Founder authority is preserved for:

- Company-wide compliance direction;
- AI Constitution compliance principles;
- enterprise Risk tolerance;
- major executive compliance authority;

suspension, escalation, investigation, or Incident Response:

# 144. Compliance Risks

| Risk | Required Response |
|---|---|
| Obligation mention treated as applicability | Require qualified applicability review |
| Applicability treated as implementation | Require mapped and implemented control |
| Documented control treated as effective | Require operating-effectiveness evidence |
| Customer request treated as contract change | Require authorized commitment process |
| Tenant request affects another Tenant | Enforce Tenant-specific authority |
| Provider certification is accepted without scope review | Verify exact certification scope |
| Agent output is treated as legal advice | Require qualified Human review |
| Training completion is treated as competence | Require assessment where material |
| Self-attestation is treated as independent assurance | Disclose assurance type |
| Sample pass is treated as full compliance | Disclose sampling limitations |
| Finding closes before verification | Block closure |
| Exception becomes permanent | Enforce expiry and remediation |
| Waiver is treated as removal of law | Preserve external obligation |
| Regional change is not propagated | Trigger applicability and control review |
| Customer evidence exposes another Customer | Enforce evidence isolation |
| Tenant evidence exposes another Tenant | Enforce Tenant isolation |
| Documentation is reported as runtime compliance | Preserve current-state boundary |
