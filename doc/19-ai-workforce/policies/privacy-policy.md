# Mianx.ai AI Workforce Privacy Policy

> **This policy defines the governed target-state privacy requirements for
> Human workers, AI Agents, Teams, Departments, Products, Projects, Customer
> Editions, Customers, Tenants, Tools, Models, memory systems, Data systems,
> providers, workflows, Tasks, and environments that collect, access, use,
> generate, infer, store, transmit, disclose, retain, correct, restrict,
> anonymize, archive, or delete Personal Data or privacy-sensitive
> information within the Mianx.ai enterprise ecosystem.**

---

# 3. Strategic Alignment

Privacy must preserve the exact Mianx.ai hierarchy:

```text
Mianx.ai Company and Governance
↓
MianX Core Platform
↓
Mianx.ai AI Operating System
↓
Shared AI Workforce
↓
Industry Operating Systems
↓
Customer Editions
↓
Autonomous Enterprise Creation at Scale
```

Privacy controls must not allow:

- a Customer Edition to override Company Governance;
- an Industry Operating System to override Core Platform privacy controls;
- a Project to redefine Product Data ownership;
- a Customer to own Mianx.ai workforce identities;
- one Customer to access another Customer’s Personal Data;
- one Tenant to access another Tenant’s Personal Data;
- an AI Agent to create its own processing purpose;
- a Model output to create a new processing basis;
- operational convenience to override retention, consent, legal hold, or
  Data-subject rights.

identifiable Human, subject to applicable qualified legal interpretation.

Examples may include:

- name;
- email address;
- telephone number;
- account identifier;
- user identifier;
- employee identifier;
- contact details;
- device information;
- network information;
- location information;
- communication content;
- activity history;
- support history;
- employment information;
- financial information;
- behavioural information;
- inferred information.

This list is illustrative and not a legal determination.

# 21. Customer Data

Customer Data means Data processed for, provided by, generated for, or

# 22. Tenant Data

Tenant Data means Data assigned to a specific Tenant boundary within a

Tenant Data must remain isolated according to:

- Tenant authorization;
- Tenant Data storage;
- Tenant memory;
- Tenant configuration;
- Tenant logs;
- Tenant exports;
- Tenant retention;
- Tenant deletion;
- Tenant Incident response.

One Tenant’s processing must not expose another Tenant’s Data.

# 24. Inferred Data

# 143. Privacy Risks

| Risk | Required Response |
|---|---|
| Data availability treated as processing authority | Require approved purpose and basis |
| Broad purpose allows unrelated reuse | Enforce purpose limitation |
| Excessive Data collection | Require minimization review |
| Consent checkbox treated as valid consent | Require complete consent evidence |
| Customer instruction treated as unlimited authority | Validate exact scope |
| Tenant assignment treated as cross-Tenant access | Enforce Tenant isolation |
| Operational Model use becomes Model training | Require separate purpose and review |
| Tool provider retains Personal Data unexpectedly | Review provider retention |
| Agent output creates Sensitive Data inference | Require review and restriction |
| Personal Data enters durable memory | Enforce memory approval and retention |
| Pseudonymized Data treated as anonymous | Preserve Personal Data controls |
| Active-record deletion treated as complete deletion | Review backups, replicas, and providers |
| Data-subject request closed before verification | Require independent completion evidence |
| Legal hold is bypassed by deletion | Block deletion |
| Automated recommendation treated as Human decision | Require meaningful Human review |
| Regional processing claim lacks evidence | Require technical verification |
