# Mianx.ai Enterprise Job Description Standard

> **This document defines the governed target-state standard for creating,
> reviewing, approving, using, changing, suspending, retiring, and auditing
> Human, AI Agent, and hybrid Job Descriptions across Mianx.ai.**

---

# 1. Purpose

This document establishes the official target-state Job Description Standard
for Mianx.ai.

It defines:

- Job Description identity;
- Job Description IDs;
- Job Description versions;
- Role linkage;
- Human applicability;
- AI Agent applicability;
- hybrid applicability;
- organizational placement;
- Department placement;
- Team placement;
- Product placement;
- Project placement;
- Customer placement;
- Tenant placement;
- reporting relationships;
- position purpose;
- position summary;
- responsibilities;
- accountabilities;
- authority;
- decision rights;
- approval rights;
- verification rights;
- prohibited authority;
- required skills;
- required capabilities;
- experience;
- education where applicable;
- training;
- certification;
- Tool requirements;
- Model requirements;
- memory requirements;
- Data requirements;
- Product scope;
- Project scope;
- Customer scope;
- Tenant scope;
- regional scope;
- environment scope;
- financial limits;
- Risk limits;
- performance expectations;
- KPIs;
- evidence;
- hiring use;
- Human assignment use;
- AI Agent assignment use;
- onboarding;
- probation;
- controlled activation;
- review;
- change control;
- suspension;
- retirement;
- Production eligibility;
- audit;
- current-state boundaries.

This document ensures that a Job Description is not considered an active
position merely because:

- a title exists;
- a vacancy is planned;
- a Role exists;
- a Job Description is written;
- a Human applies;
- a Human is hired;
- an AI Agent is defined;
- an Agent can perform the work;
- a Department requests additional capacity;
- a manager assigns Tasks;
- Tool access is available;
- performance expectations are documented;
- documentation is marked complete.

This document does not independently:

- create a Role;
- create a position;
- create employment;
- create an AI Agent;
- assign a Human;
- assign an Agent;
- activate authority;
- grant system access;
- grant Product access;
- grant Customer access;
- grant Tenant access;
- establish compensation;
- prove competence;
- prove performance;
- authorize Production operation.

# 3. Strategic Alignment

Job Descriptions must preserve the exact Mianx.ai hierarchy:

```text
Mianx.ai Company and Governance
↓
MianX Core Platform
↓
Mianx.ai AI Operating System
↓
Shared AI Workforce
↓
Industry Operating Systems
↓
Customer Editions
↓
Autonomous Enterprise Creation at Scale
```

Job Descriptions must not allow:

- a Customer Edition position to override Company Governance;
- an Industry Operating System position to override Core Platform authority;
- a Project position to redefine permanent Product ownership;
- a Customer-specific position to access another Customer;
- a Tenant-specific position to access another Tenant;
- an AI Agent position to claim Human legal accountability;
- a Job Description to create Founder authority;
- a position title to create unrestricted system permissions;
- performance pressure to bypass Security, Privacy, Ethics, or Compliance.

- create a position from it;

# 10. Founder Authority

Founder authority is preserved for:

- Company identity;
- enterprise vision;
- AI Constitution;
- Founder-reserved positions;
- Founder Office structure;
- major executive positions;
- unrestricted AI authority;
- major legal or financial positions;
- Company-wide Production authority;
- matters explicitly reserved to the Founder.

No Job Description may fabricate Founder approval or Founder appointment.

# 14. Job Description Versioning

```text

=
Position purpose, linked Role, accountability, authority, position type,
or material scope change

=
Responsibilities, skills, capabilities, Tools, Models, memory, Data,
performance, KPI, or reporting change

=
Clarification, metadata correction, formatting, or non-material wording change
```

Existing positions must be reviewed when a linked Job Description receives a
material version change.

# 92. Lifecycle Rules

A Job Description must not move to:

- `ORGANIZATIONAL-REVIEW` without an owner;
- `AUTHORITY-REVIEW` without Role linkage;
- `APPROVED` without responsibility and authority review;
- `AVAILABLE-FOR-POSITION-CREATION` without eligibility requirements;
- `POSITION-CREATED` without approved organizational need;
- `ASSIGNED` without a valid Role assignment;
- `ACTIVE` without position activation;
- `PRODUCTION-ACTIVE` without Production gates;
- `RENEWED` without review;
- `RETIRED` without affected-position treatment;
- `ARCHIVED` before retention requirements are satisfied.
