# Mianx.ai Enterprise Role Skill Matrix Standard

> **This document defines the governed target-state standard for mapping,
> assessing, verifying, developing, renewing, suspending, and auditing the
> skills required by Human, AI Agent, and hybrid Roles and Job Descriptions
> across the Mianx.ai enterprise ecosystem.**

---

# 1. Purpose

This document establishes the official target-state Enterprise Role Skill
Matrix Standard for Mianx.ai.

It defines:

- Skill Matrix identity;
- Skill Matrix IDs;
- Role-to-skill mapping;
- Job Description-to-skill mapping;
- Human skills;
- AI Agent skills;
- hybrid skills;
- skill categories;
- proficiency levels;
- mandatory skills;
- preferred skills;
- conditional skills;
- foundational skills;
- leadership skills;
- communication skills;
- technical skills;
- operational skills;
- Product skills;
- Project skills;
- Customer skills;
- Tenant skills;
- Tool skills;
- Model skills;
- memory skills;
- Data skills;
- Security skills;
- Privacy skills;
- Ethics skills;
- Compliance skills;
- financial skills;
- assurance skills;
- Incident skills;
- capability relationships;
- experience relationships;
- training relationships;
- certification relationships;
- assessment methods;
- evidence requirements;
- skill verification;
- skill gaps;
- learning plans;
- remediation;
- assignment eligibility;
- renewal;

- Project scope;
- Customer scope;
- Tenant scope;
- regional scope;
- environment scope;
- performance linkage;
- audit;
- Production Skill gates;
- current-state boundaries.

This document ensures that a subject is not considered skilled merely because:

- a skill is listed in a Role;
- a skill appears in a Job Description;
- a Human claims experience;
- an Agent prompt mentions a capability;
- a training course was assigned;
- a training course was completed;
- a certification was issued;
- a Tool is available;
- a Model can perform a Task;
- a Task was completed once;
- a manager gives a positive review;
- an Agent produces a confident answer;
- documentation is marked complete.

This document does not independently:

- create a skill;
- prove skill possession;
- prove proficiency;
- prove capability;
- prove experience;
- create Role eligibility;
- create Role assignment;
- create position assignment;
- create authority;
- grant Tool access;
- grant Model access;
- grant memory access;
- grant Data access;
- prove runtime performance;
- authorize Production operation.

# 3. Strategic Alignment

Skill Governance must preserve the exact Mianx.ai hierarchy:

```text
Mianx.ai Company and Governance
↓
MianX Core Platform
↓
Mianx.ai AI Operating System
↓
Shared AI Workforce
↓
Industry Operating Systems
↓
Customer Editions
↓
Autonomous Enterprise Creation at Scale
```

Skill design must not allow:

- a Customer Edition skill requirement to override Company Governance;
- an Industry Operating System skill to create Core Platform authority;
- a Project skill to redefine permanent Product ownership;
- a Customer-specific skill to create access to another Customer;
- a Tenant-specific skill to create access to another Tenant;
- an AI Agent skill to replace qualified Human accountability;
- technical proficiency to create legal or financial authority;
- high performance to bypass Role, Security, Privacy, Ethics, or Compliance
  boundaries.

The Enterprise Role Skill Matrix must follow:

1. Founder sovereignty;
2. qualified Human accountability;
3. approved Skill Registry linkage;
4. approved Role and Job Description linkage;
5. explicit skill requirements;
6. defined proficiency levels;
7. subject-type-specific assessment;
8. evidence before verification;
9. minimum necessary skill requirements;
10. current rather than historical proficiency;
11. Human and Agent assessment separation;
12. Product and Project context;
13. Customer and Tenant isolation;
14. region and environment awareness;
15. renewal and expiry;
16. gap transparency;
17. remediation before Production eligibility;
18. independent verification where required;
19. performance linkage without authority inflation;
20. no documentation-as-runtime claims.

# 9. Skill Authority

Skill authority defines who may:

- create a Skill Matrix;
- map skills to Roles;
- map skills to Job Descriptions;
- define proficiency levels;
- design assessments;
- conduct assessments;
- verify evidence;
- identify skill gaps;
- approve learning plans;
- approve remediation;
- suspend a Skill status;
- revoke verification;
- approve Production Skill eligibility;
- audit Skill records.

Skill authority must be:

- explicit;
- Role-based;
- skill-family-specific;
- subject-type-specific;
- Product-aware;
- Project-aware;
- Customer-aware;
- Tenant-aware;
- region-aware;
- environment-aware;
- time-bounded;
- reviewable;
- revocable;
- evidence-backed.

# 10. Founder Authority

Founder authority is preserved for:

- enterprise vision;
- AI Constitution;
- enterprise workforce model;
- Founder-reserved Roles;
- major executive requirements;
- unrestricted AI autonomy;
- critical Production eligibility standards;
- Company-wide skill assurance direction;
- existential Risk;
- matters explicitly reserved to the Founder.

No Skill Matrix, assessor, Agent output, certification, or performance score
may fabricate Founder approval.

# 11. Qualified Human Accountability

Qualified Human accountability is mandatory for:

- legal skills;
- regulatory skills;
- financial authority-related skills;
- employment decision skills;
- Security Incident command skills;
- Privacy Incident notification skills;
- compliance attestation skills;
- high-impact Human decision skills;
- audit authority skills;
- Production restoration skills;
- irreversible destructive-operation skills;
- Founder-reserved matters.

AI Agent skill verification may support but must not replace required Human
accountability.

# 51. Proficiency Model

The proposed proficiency model is:

```text
P0 — Not Assessed

P1 — Awareness

P2 — Foundational

P3 — Working

P4 — Advanced

P5 — Expert

P6 — Authority-Level Human Specialist or Independently Verified Advanced Agent
```

Proficiency labels must be supported by defined criteria.

---

# 52. Proficiency Level P0

`P0 — Not Assessed` means:

- no valid assessment exists;
- no current proficiency claim may be made;
- assignment eligibility must not assume competence;
- Production activation is prohibited where the skill is mandatory.

---

# 53. Proficiency Level P1

`P1 — Awareness` means the subject can:

- recognize basic concepts;
- understand terminology;
- identify when assistance is needed;
- follow simple instructions;
- escalate uncertainty.

P1 does not authorize independent execution.

---

# 54. Proficiency Level P2

`P2 — Foundational` means the subject can:

- perform simple work under supervision;
- follow defined procedures;
- use approved templates;
- identify common errors;
- preserve required evidence;
- escalate exceptions.

---

# 55. Proficiency Level P3

`P3 — Working` means the subject can:

- perform normal work independently within scope;
- apply approved standards;
- handle common variations;
- identify material Risks;
- produce usable evidence;
- request review when required.

---

# 56. Proficiency Level P4

`P4 — Advanced` means the subject can:

- handle complex work;
- adapt approved methods;
- review others’ work;
- diagnose difficult failures;
- improve workflows;
- mentor or support lower proficiency;
- contribute to skill standards.

Advanced proficiency does not independently create approval authority.

---

# 57. Proficiency Level P5

`P5 — Expert` means the subject can:

- solve novel problems;
- design advanced methods;
- define assessment criteria;
- review complex evidence;
- advise Governance;
- lead difficult remediation;
- contribute to enterprise standards.

Expert status must remain scope-specific.

---

# 58. Proficiency Level P6

`P6 — Authority-Level Human Specialist or Independently Verified Advanced Agent`
means:

- the subject has exceptional verified proficiency;
- exact authority remains separately assigned;
- Human legal or regulated authority still requires qualified Human status;
- AI Agent P6 status remains technically bounded;
- independent verification is mandatory;
- periodic renewal is mandatory;
- Production scope must be explicit.

---
