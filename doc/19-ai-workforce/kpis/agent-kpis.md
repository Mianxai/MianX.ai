# Mianx.ai AI Agent Key Performance Indicators

> **This document defines the governed target-state KPI framework used to
> measure the effectiveness, quality, reliability, safety, Security, privacy,
> compliance, efficiency, cost, capacity, collaboration, evidence quality,
> Customer contribution, and business contribution of individual Mianx.ai AI
> Agents.**

---

because it:

- produces many messages;
- accepts many Tasks;

- operates at high utilization.

- implement KPI instrumentation;

- establish measured Agent baselines;
- approve numeric targets;
- approve KPI weights;
- activate Agent scorecards;
- authorize automated performance enforcement;
- activate AI Agents;
- prove runtime performance;
- prove Production readiness.

# 5. Core KPI Principles

## 5.1 KPIs Must Be Evidence-Based

Every material KPI result must reference:

- KPI Definition;
- KPI version;
- Agent identity;
- measurement scope;
- measurement window;
- source Data;
- calculation;
- Data-quality status;
- verifier;
- evidence.

---

## 5.2 Activity Is Not Outcome

The following must not independently be treated as performance:

- message count;
- token count;
- Tool-call count;
- file count;
- prompt count;
- Task acceptance count;
- active time.

---

## 5.3 Completion Is Not Acceptance

An Agent-reported completion is not equivalent to:

- evidence-complete work;
- reviewed work;
- accepted work;
- Customer-approved work;
- business value.

---

## 5.4 Quality Cannot Be Averaged Away

High volume, low cost, or low latency must not compensate for:

- fabricated evidence;
- cross-Tenant leakage;
- secret exposure;
- critical Security failure;
- critical privacy failure;
- unauthorized Production action;
- destructive action without approval.

---

## 5.5 KPI Results Must Be Scope-Aware

A KPI result must be attributable to the exact:

- Agent;
- version;
- Role;
- Product;
- Project;
- Tenant;
- Customer;
- environment;
- workflow;
- Task class;
- Risk class;
- measurement window.

---

## 5.6 Baselines Must Precede Targets

Numeric targets should normally be approved only after:

- instrumentation exists;
- Data quality is verified;
- sufficient samples exist;
- a baseline is measured;
- workload complexity is understood;
- variability is understood;
- Risk is assessed.

---

## 5.7 Planned Values Must Be Clearly Labelled

Planned KPI values must be labelled:

```text
PROPOSED

NOT MEASURED

NOT APPROVED

NOT A RUNTIME RESULT
```

---

## 5.8 Failures Must Remain Visible

The KPI system must include:

- failed Tasks;
- rejected outputs;
- timeouts;
- retries;
- rollbacks;
- partial results;
- evidence failures;
- Human corrections;
- reopened work;
- incidents.

---

## 5.9 Human Contribution Must Be Attributed

Agent performance must identify Human:

- supervision;
- clarification;
- correction;
- review;
- approval;
- recovery;
- rework;
- escalation.

---

## 5.10 Cost Must Be Complete

Agent cost must include:

- Model usage;
- Tool usage;
- infrastructure;
- memory;
- storage;
- retries;
- failures;
- Human review;
- remediation;
- incident recovery.

---

## 5.11 KPIs Must Be Comparable

KPI comparison requires compatible:

- Task type;
- complexity;
- Risk;
- Product;
- Project;
- environment;
- Data;
- Model;
- Tool;
- review requirements;
- measurement window.

---

## 5.12 Agents Must Not Approve Their Own KPIs

An Agent may produce execution evidence.

It must not be the sole authority for:

- KPI Definition;
- baseline approval;
- target approval;
- scorecard approval;
- Production promotion;
- suspension removal.

# 7. Metric

A metric is a quantitative or qualitative measurement.

Examples:

- Task count;
- failure count;
- latency;
- cost;
- review findings.

Not every metric is a KPI.

---

# 8. Key Performance Indicator

A KPI is a governed metric selected because it materially indicates whether an
Agent is achieving an approved operational, quality, safety, Customer, or
business objective.

A KPI must have:

- purpose;
- owner;
- formula;
- unit;
- scope;
- measurement window;
- baseline;
- target where approved;
- threshold;
- evidence;
- response.

---

# 9. KPI Target

A target is an approved desired KPI value or range.

A target must not be inferred from:

- architecture documents;
- Roadmap language;
- aspirational statements;
- provider benchmarks;
- competitor claims;
- one successful test.

---

# 10. KPI Threshold

A threshold defines the operational response when a KPI enters a defined range.

Threshold bands may include:

```text
NOT-MEASURED

HEALTHY

WATCH

DEGRADED

CRITICAL

SUSPENDED
```

---

# 11. Hard-Stop KPI

A hard-stop KPI represents a condition that must not be offset by other KPI
scores.

Examples include:

- confirmed cross-Tenant leakage;
- fabricated approval;
- fabricated evidence;
- secret exposure;
- unauthorized Production action;
- ignored suspension;
- unauthorized financial execution.

---

An Agent KPI Profile defines the exact KPIs that apply to one Agent
configuration.

It should identify:

- Agent Definition;
- Agent Instance;
- Role;
- Agent type;
- Product;
- Project;
- Tenant;
- Customer;
- environment;
- Risk;
- required KPIs;
- optional KPIs;
- hard-stop KPIs;
- review cadence;
- evidence requirements;
- owners.

---

# 13. Agent KPI Scorecard

An Agent KPI Scorecard records the measured KPI results for one Agent and one
measurement window.

It must show:

- Agent identity;
- scope;
- window;
- KPI values;
- baselines;
- targets;
- thresholds;
- hard stops;
- Data quality;
- limitations;
- evidence;
- remediation;
- overall status.

# 23. Task Completion Rate

```text
Task Completion Rate
=
Tasks Marked Completed
/
Eligible Assigned Tasks
```

This KPI must not be represented as verified completion.

---

# 24. Verified Completion Rate

```text
Verified Completion Rate
=
Tasks Completed with Valid Mandatory Evidence
/
Eligible Assigned Tasks
```

Evidence must satisfy the Verifiable-Work Envelope requirements.

---

# 25. Accepted Outcome Rate

```text
Accepted Outcome Rate
=
Outputs Accepted by Authorized Reviewer
/
Eligible Reviewed Outputs
```

Agent self-acceptance must not count.
