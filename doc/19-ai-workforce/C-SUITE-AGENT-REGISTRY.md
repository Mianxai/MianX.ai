# 17. Definition ID Versus Instance ID

Example:

```yaml
agent_definition_id: mianx.cto.v1
agent_instance_id: runtime-generated-and-separately-unique
```

The definition ID identifies the governed executive specification.

The instance ID identifies a particular runtime Agent.

Multiple runtime instances based on one executive definition are prohibited
unless:

- a verified need exists;
- responsibilities do not conflict;
- each instance has a unique allocation;
- Product, Project, Tenant, Customer, and environment scopes are isolated;
- independent ownership is assigned;
- duplicate authority Risk is reviewed;
- Founder approval exists where required.

# 22. Executive Lifecycle State Definitions

| State | Meaning |
|---|---|
| `Proposed` | Definition or instance need is being considered |
| `Designed` | Mandate and controls are substantively defined |
| `In Review` | Required domain reviews are underway |
| `Approved Definition` | Role and Agent definition are approved |
| `Registered` | Runtime instance identity exists |
| `Provisioned` | Approved runtime configuration exists |
| `Evaluated` | Required evaluation has completed |
| `Certified` | Required high-risk certification is valid |
| `Allocated` | Instance is assigned to approved scope |
| `Active` | Instance may perform approved bounded work |
| `Live-Tested` | Controlled live work has passed review |
| `Production-Controlled` | Defined Production authority and operational controls are active |
| `Restricted` | Authority, scope, Tools, Models, or capacity are reduced |
| `Degraded` | Instance remains available with a material health limitation |
| `Suspended` | New execution is blocked |
| `Retiring` | Controlled removal is underway |
| `Retired` | Operational authority is removed |
| `Revoked` | Authority was withdrawn because of Risk or violation |
| `Archived` | Historical record remains, with no executable authority |

|---|---|
