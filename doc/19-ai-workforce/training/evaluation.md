# Mianx.ai Enterprise Human and AI Workforce Evaluation Standard

> **This document defines the governed target-state standard for evaluating
> Humans, AI Agents, Roles, skills, capabilities, Tools, Models, memory
> behavior, workflows, Products, Projects, Customers, Tenants, Security,
> Privacy, Ethics, Compliance, operational performance, and
> Production-readiness conditions across Mianx.ai. It defines evaluation
> authority, independence, identity, test design, rubrics, scoring,
> critical failures, evidence, retesting, remediation, appeals, integrity,
> bias controls, auditability, and separation from certification and
> Production authorization.**

---

# 1. Purpose

The purpose of this standard is to ensure that workforce evaluation across
Mianx.ai is:

- objective where possible;
- evidence-based;
- repeatable;
- auditable;
- Role-aware;
- Risk-aware;
- version-aware;
- Customer-isolated;
- Tenant-isolated;
- independent from self-approval;
- separate from training completion;
- separate from certification;
- separate from operational authority;
- separate from Production authorization.

This standard governs evaluations involving:

- Human workers;
- AI Agents;
- Human-AI Teams;
- Roles;
- skills;
- capabilities;
- Tools;
- Models;
- memory;
- workflows;
- Products;
- Projects;
- Customer contexts;
- Tenant contexts;
- Security;
- Privacy;
- Ethics;
- Compliance;
- performance;
- Production readiness.

This document does not independently:

- certify a learner;
- verify every Skill Registry claim;
- verify every Capability Registry claim;
- appoint a Human to a Role;
- activate an Agent;
- authorize a Tool;
- authorize a Model;
- grant Customer access;
- grant Tenant access;
- grant Production access;
- authorize autonomous operation.

# 7. Evaluation Principles

Every material evaluation should follow:

1. Founder sovereignty;
2. qualified Human accountability;
3. exact subject identity;
4. exact version identity;
5. evaluator competence;
6. evaluator independence where required;
7. pre-defined criteria;
8. pre-defined critical failures;
9. controlled test conditions;
10. reproducible evidence;
11. Customer isolation;
12. Tenant isolation;
13. no hidden score manipulation;
14. failure preservation;
15. remediation rather than fabricated passing;
16. evaluation separate from authorization.

# 8. Evaluation Authority

Evaluation authority defines who may:

- create Evaluation Definitions;
- approve Evaluation Definitions;
- select evaluators;
- run evaluations;
- score evaluations;
- verify results;
- invalidate results;
- approve retests;
- hear appeals;
- audit evidence;
- retire obsolete evaluations.

Evaluation authority must not automatically create operational authority.

---

# 9. Founder Sovereignty

Founder-reserved Evaluation matters may include:

- Founder Office Role readiness;
- executive-level evaluation requirements;
- high-autonomy AI Agent readiness;
- enterprise-critical decision Role evaluation;
- strategic Governance competency;
- material changes to Production-readiness evaluation standards.

No system may fabricate Founder approval.

# 10. Qualified Human Accountability

Qualified Human accountability is required for material evaluations
involving:

- high-autonomy AI Agents;
- Production eligibility;
- Security-sensitive roles;
- Privacy-sensitive roles;
- legal or Compliance-sensitive work;
- financial authority;
- Customer commitments;
- Tenant-wide impact;
- certification;
- high-Risk workflow operation.

# 13. Conflict of Interest

An evaluator must disclose material conflicts.

Potential conflicts include:

- evaluating own work;
- evaluating a direct incentive-linked outcome;
- evaluating an Agent the evaluator solely designed;
- evaluating a Team where evaluator controls all outcome metrics;
- financial interest in a pass result.

# 110. Anti-Gaming Controls

Evaluation Governance must prevent:

- changing passing score after seeing results;
- deleting hard test cases to improve pass rate;
- excluding failed runs from metrics;
- repeatedly retesting until one pass appears;
- using only best attempt without history;
- allowing subjects to evaluate themselves;
- leaking hidden test cases;
- changing Agent version after test while claiming same result;
- changing Model version without reevaluation;
- treating Customer A evaluation as Customer B readiness;
- treating Tenant A evaluation as Tenant B readiness;
- using benchmark performance as Production authorization.
