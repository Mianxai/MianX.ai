# Mianx.ai Enterprise Human and AI Workforce Learning Path Standard

> **This document defines the governed target-state model for structured
> Human and AI Agent learning progression across Mianx.ai. It establishes
> Learning Path identity, sequencing, prerequisites, entry criteria,
> competency stages, mandatory and elective learning, branching,
> equivalency, prior-learning recognition, Role-based paths, leadership
> paths, skill and capability development, Tool, Model, memory, workflow,
> Product, Project, Customer, Tenant, Security, Privacy, Ethics, Compliance,
> supervised practice, evaluation gates, remediation, certification,
> recertification, expiry, evidence, audit, and Production-readiness
> relationships.**

---

# 1. Purpose

The purpose of this standard is to ensure that Mianx.ai workforce learning
is not a random collection of courses or documents.

Every governed Learning Path should define:

- who must learn;
- why the learning is required;
- what must be learned;
- in what sequence;
- which prerequisites apply;
- which stages are mandatory;
- which stages are elective;
- where practical demonstration is required;
- where evaluation gates apply;
- where remediation is required;
- when certification is required;
- when recertification is required;
- what evidence must exist;
- how Production readiness remains separately controlled.

This standard applies to:

- Humans;
- AI Agents;
- Roles;
- leaders;
- Departments;
- Teams;
- skills;
- capabilities;
- Tools;
- Models;
- memory;
- workflows;
- Products;
- Projects;
- Shared Services;
- Customers;
- Tenants;
- Customer Editions;
- Security;
- Privacy;
- Ethics;
- Compliance;
- Risk;
- Incident readiness;
- Production readiness.

This document does not independently:

- create training content;
- create a Training Program;
- assign a learner;
- verify a skill;
- verify a capability;
- issue certification;
- appoint a Human to a Role;
- activate an Agent;
- grant access;
- authorize Customer scope;
- authorize Tenant scope;
- authorize Production.

2. qualified Human accountability;
3. learner identity before assignment;
4. explicit purpose;
5. exact target Role or capability;

# 13. Learning Path Version

Recommended:

```text
MAJOR.MINOR.PATCH
```

- path purpose;
- target Role;
- major competency stages;
- mandatory learning;
- certification gate;
- Customer/Tenant boundary;
- Production-readiness requirements.

A `MINOR` change may apply to:

- module sequence;
- Tool updates;
- Model updates;
- workflow updates;
- additional electives;
- evaluation changes.

A `PATCH` may cover non-material corrections.

- reuse Customer A learning evidence for Customer B without approval;
