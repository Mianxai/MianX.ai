# Purpose

Empty state illustrations help users understand why content is unavailable and guide them toward the next meaningful action.

Instead of presenting a blank screen, empty states provide helpful context, reduce confusion, and encourage user engagement.

This document defines enterprise standards for creating consistent, accessible, and user-friendly empty state illustrations.

---

# Objectives

The Empty State Illustration System aims to:

- Reduce user confusion
- Improve first-time experience
- Encourage feature adoption
- Guide user actions
- Reduce abandonment
- Maintain visual consistency
- Improve accessibility
- Support all products
- Support AI-assisted experiences
- Create reusable illustration assets

---

# Scope

These standards apply to:

- Empty Dashboards
- Empty Projects
- Empty Tasks
- Empty Notifications
- Empty Messages
- Empty Files
- Empty Search Results
- No Internet
- No Permissions
- Error Recovery
- AI Empty States
- First-Time Experiences
- Loading Fallbacks

---

# Empty State Philosophy

Every empty state should answer three questions:

```text
What happened?

↓

Why did it happen?

↓

What should the user do next?
```

An empty state should never leave users without guidance.

---

# Core Principles

Every empty state illustration should be:

- Helpful
- Friendly
- Professional
- Minimal
- Positive
- Actionable
- Accessible
- Brand Consistent

# First-Time Experience

Purpose:

Introduce users to a feature before any content exists.

Examples:

- New Workspace
- New Dashboard
- New Project
- New Team
- New Organization

Primary CTA examples:

- Create Project
- Add Task
- Invite Team
- Upload File

---

# No Data

Used when data has not yet been created.

Examples:

- No Orders
- No Customers
- No Reports
- No Products
- No Employees

Illustration should encourage creation rather than imply an error.

---

# No Search Results

Used when search returns zero matches.

Illustration message:

```text
Nothing matched your search.

Try different keywords or adjust your filters.
```

Recommended actions:

- Clear Filters
- Search Again
- Browse All

---

# No Internet

Purpose:

Inform users that the application cannot reach online services.

Illustration should communicate:

- Temporary issue
- Retry available
- Offline mode (if supported)

Recommended CTA:

- Retry Connection

---

# Offline Mode

If offline functionality exists:

Illustration should explain:

- Local data availability
- Synchronization status
- Pending uploads

Recommended actions:

- Continue Offline
- Retry Sync

---

# No Notifications

Illustration should reassure users.

Example message:

```text
You're all caught up.
```

Avoid making users feel they are missing something.

---

# No Messages

Illustration communicates:

- Inbox is empty
- No conversations started

Recommended CTA:

- Start Conversation

---

# No Projects

Illustration should explain:

Projects help organize work.

Recommended CTA:

- Create Project

---

# No Tasks

Illustration should encourage productivity.

Suggested CTA:

- Create Task

---

# No Files

Illustration explains:

No files have been uploaded.

Recommended CTA:

- Upload File

---

# Permission Denied

Illustration communicates:

The user does not currently have access.

Avoid using alarming imagery.

Recommended actions:

- Request Access
- Contact Administrator

---

# AI Empty State

AI-related empty states include:

- No AI Agents
- No AI Memory
- No AI Conversations
- No AI Workflows

Recommended CTA:

- Create AI Agent
- Start Conversation
- Build Workflow

---

# Error Recovery

When recovery is possible:

Illustration should communicate:

- Something went wrong
- Recovery is available

Recommended CTA:

- Retry
- Refresh
- Contact Support

---

# Maintenance Mode

Illustration explains:

System maintenance is in progress.

Recommended actions:

- Refresh Later
- View Status Page

---

# Visual Style

Follow:

- illustration-style.md
- illustration-guidelines.md

Characteristics:

- Flat
- Minimal
- Friendly
- Calm
- Professional

---

# Composition

Illustrations should contain:

- Primary Object
- Supporting Object
- Minimal Background
- Clear Focus Area

Avoid unnecessary decorative elements.

---

# Characters

Characters should appear:

- Calm
- Helpful
- Positive
- Encouraging

Avoid:

- Frustrated
- Angry
- Sad
- Panicked

---

# Objects

Examples:

- Empty Folder
- Empty Inbox
- Search Box
- Dashboard
- Cloud
- AI Assistant
- Workspace
- Document

Objects should match the Design System.

---

# Color Usage

Recommended balance:

| Color | Usage |
|--------|-------|
| Neutral | 70% |
| Primary | 20% |
| Accent | 10% |

Avoid warning colors unless communicating an actual warning.

---

# Messaging Guidelines

Headlines should be:

- Short
- Friendly
- Clear

Examples:

```text
No Projects Yet

No Search Results

Nothing Here Yet

You're All Caught Up

Let's Get Started
```

---

# CTA Guidelines

Every empty state should include a meaningful next action whenever possible.

Examples:

- Create
- Upload
- Invite
- Retry
- Refresh
- Learn More
- Browse
- Contact Support

Avoid dead ends.

---

# Responsive Design

Illustrations should adapt to:

- Desktop
- Tablet
- Mobile

Mobile layouts should:

- Reduce decorative objects
- Preserve whitespace
- Keep CTA visible

---

# Accessibility

Illustrations should:

- Maintain sufficient contrast
- Avoid relying only on color
- Include descriptive alternative text when informative
- Be ignored by assistive technologies when decorative

---

# Performance

Illustrations should:

- Use optimized SVG
- Support lazy loading
- Minimize file size
- Scale without quality loss

---

# AI-Assisted Creation

AI may assist with:

- Concept generation
- Composition ideas
- Variants
- Color exploration

Human approval is required before production use.

# Common Mistakes

Avoid:

- Blank screens
- Negative messaging
- Decorative overload
- Missing CTA
- Confusing illustrations
- Generic stock artwork
- Mixed illustration styles
- Overly detailed scenes

---

# Best Practices

- Explain the situation clearly.
- Always suggest the next step.
- Maintain a positive tone.
- Keep illustrations lightweight.
- Reuse approved assets.
- Follow the illustration style guide.
- Optimize every export.
- Test with real users.
- Preserve accessibility.
- Keep messaging concise.
