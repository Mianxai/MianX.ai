# Purpose

This document defines the official standards for event logos created or used within the Mianx.ai ecosystem.

It ensures that every event identity is:

- Consistent with the Mianx.ai corporate brand
- Appropriate for its audience and purpose
- Clearly linked to the parent organization
- Properly approved
- Time-bound
- Easy to archive after completion
- Safe for sponsor and partner co-branding

---

# Objectives

- Standardize event logo creation.
- Maintain corporate brand consistency.
- Prevent unnecessary permanent sub-brands.
- Support internal and external events.
- Define sponsor and partner logo usage.
- Separate temporary event identity from permanent company identity.
- Ensure event assets expire correctly.
- Preserve complete event history.
- Enable scalable use across recurring events.
- Support AI-assisted asset discovery and compliance.

# Core Principle

An event logo represents a time-bound program or experience.

It must not:

- Replace the Mianx.ai corporate logo
- Appear to represent a separate company
- Become a permanent product brand without approval
- Continue active use after the event lifecycle ends
- Misrepresent sponsor or partner relationships

The Mianx.ai corporate identity must remain visible in official event communication.

# Event Identity Levels

## Level 1 — Corporate Event

A major organization-wide event.

Examples:

- Annual Summit
- Company Conference
- Enterprise Launch Event
- Global Town Hall

May receive a complete approved event identity.

---

## Level 2 — Department Event

An event owned by a specific department.

Examples:

- Engineering Workshop
- Security Awareness Week
- Marketing Strategy Session
- Finance Planning Forum

The department and Mianx.ai identities must remain primary.

---

## Level 3 — Product Event

An event related to a product or platform.

Examples:

- Product Launch
- Feature Release Webinar
- Developer Conference
- Customer Training Session

The product logo and corporate identity must follow the approved hierarchy.

---

## Level 4 — Partner Event

A jointly organized event.

Examples:

- Joint Webinar
- Partner Workshop
- Integration Launch
- Sponsored Conference

Co-branding terms must be documented before design begins.

---

## Level 5 — Internal Session

A limited internal activity.

Examples:

- Team Workshop
- Sprint Review
- Knowledge Session
- Department Training
- Planning Day

A dedicated logo is usually unnecessary.

Use a title treatment or approved event badge instead.

# Event Identity Decision

Before creating a new event logo, determine whether the event actually requires one.

Use a dedicated event logo only when:

- The event is externally visible.
- The event is strategically significant.
- The event is recurring.
- The event requires registration or promotion.
- The event has multiple communication channels.
- The event has an approved marketing plan.
- The event requires sponsor or partner visibility.

Use a simple title treatment when:

- The event is internal.
- The event is one-time and small.
- The event has limited audience.
- The event does not require public promotion.
- Existing corporate templates are sufficient.

Every event logo should include a documented clear-space rule.

Recommended unit:


# File Naming Convention

Use lowercase kebab-case.

Pattern:

```text
{event-name}-{edition}-{asset-type}-{variant}-{version}.{extension}
```

Examples:

```text
ai-innovation-summit-2026-logo-primary-v1.svg

security-week-2026-logo-dark-v1.svg

product-launch-2026-event-badge-v1.svg

engineering-conference-2026-stage-logo-v1.pdf

ai-summit-2026-social-avatar-v1.png
```

Avoid:

```text
event-logo-final.png

conference-new-logo.svg

summit-logo-latest-final.ai

webinar-logo-2-fixed.png
```

# Expiry Policy

Event logos should expire from active promotional use after:

- The event is completed.
- Post-event communication ends.
- Sponsor rights expire.
- Campaign pages are archived.
- Registration is closed.
- Future editions replace the current one.

An expired event logo must not be used to promote a new edition.

---

# Recurring Event Migration

When a new edition is created:

- Preserve the core event identity.
- Create a new edition layer.
- Update dates and location.
- Review sponsor agreements.
- Update metadata.
- Generate new exports.
- Archive old promotional assets.
- Maintain historical pages separately.

---

# Archive Policy

After completion, archive:

- Master Logo
- Edition Assets
- Sponsor Lockups
- Social Media Graphics
- Stage Graphics
- Livestream Assets
- Presentation Templates
- Merchandise Files
- Approval Records
- Metadata
- Final Event Report

Archived assets must remain read-only.

---

# Event Cancellation

If an event is cancelled:

- Stop promotional usage.
- Update event status.
- Remove active registration assets.
- Notify sponsors and partners.
- Update website and social media.
- Preserve the event identity for audit purposes.
- Mark all assets as cancelled or archived.
- Record the cancellation reason and date.

Do not delete event records.

---

# Event Postponement

If an event is postponed:

- Update the official date.
- Review logo and edition assets.
- Add a temporary postponement notice separately.
- Update all active channels.
- Confirm sponsor validity.
- Regenerate date-dependent exports.
- Preserve prior published versions for audit.

Do not modify master logo artwork merely to display postponement status.

# Audit Requirements

Event logo audits should verify:

- Correct event identity usage
- Correct event edition
- Accurate dates
- Current sponsor permissions
- Correct partner logos
- Active usage period
- Expired promotional assets
- Missing metadata
- Unauthorized variants
- Missing source files
- Incomplete archive records
- Accessibility compliance

Recommended frequency:

```text
Before Launch

During Active Promotion

Immediately After Event

Quarterly Archive Review
```

# Common Mistakes

Avoid:

- Creating a logo for every small internal meeting.
- Allowing event branding to overpower Mianx.ai.
- Permanently embedding the year into the core event master.
- Reusing an old edition logo.
- Adding sponsors without approval.
- Using incorrect event dates.
- Leaving registration graphics active after completion.
- Failing to archive sponsor assets.
- Creating multiple identities for the same event.
- Treating a one-time event as a permanent product brand.
- Using event colors that conflict with accessibility.
- Publishing confidential event details.
- Failing to track event-logo expiry.

# Best Practices

- Create a dedicated logo only when the event scale justifies it.
- Keep the Mianx.ai corporate relationship visible.
- Separate permanent event identity from edition details.
- Treat sponsor logos as governed third-party assets.
- Define promotion and archive dates before launch.
- Maintain one official Event ID.
- Use reusable event templates.
- Preserve source files and approval records.
- Archive completed event assets as read-only.
- Review recurring event identities before each edition.
- Automate expiry and sponsor-rights alerts.
- Keep events, marketing, partnerships, legal, and asset records synchronized.
