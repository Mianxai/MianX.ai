# Purpose

This document defines the official visual identity standards for all AI agents, AI teams, AI departments, and autonomous workforce roles operating within the Mianx.ai ecosystem.

The goal is to make every AI role recognizable and traceable without turning each agent into a separate commercial brand.

AI workforce identities must remain connected to:

- Mianx.ai Corporate Brand
- Official Department
- Agent Role
- Capability Level
- Operational Status
- Governance Record

---

# Objectives

- Standardize AI agent visual identities.
- Distinguish agents from departments and products.
- Make agent roles easy to identify.
- Support scalable creation of hundreds of agents.
- Prevent random or inconsistent avatars.
- Enable reliable use in dashboards and workflows.
- Support machine-readable asset discovery.
- Maintain complete version and approval history.
- Protect the parent Mianx.ai brand.

An AI agent identity represents an executable organizational role.

It does not represent:

- A separate company
- A separate product
- A legal person
- An independent department
- A public commercial brand

Every AI workforce identity must remain subordinate to the Mianx.ai corporate identity.

# Avatar Design Principles

Agent avatars should be:

- Simple
- Recognizable
- Professional
- Consistent
- Scalable
- Role-oriented
- Department-linked
- Accessible
- Suitable for light and dark themes

Avoid:

- Photorealistic human faces
- Celebrity likenesses
- Offensive imagery
- Unlicensed characters
- Random cartoon styles
- Overly complex details
- Misleading human representation

---

# Human-like Representation

When human-like avatars are used, they must clearly represent an AI role rather than a real employee.

Recommended visual signals may include:

- Abstract digital patterns
- Geometric framing
- AI role badge
- Department code
- Non-photorealistic styling
- Clear agent label

AI identities must not be designed to impersonate real people.

# Operational Status Badges

Approved operational statuses may include:

| Status | Meaning |
|--------|---------|
| Draft | Agent configuration is incomplete |
| Testing | Agent is undergoing validation |
| Active | Agent is approved for operation |
| Paused | Agent is temporarily unavailable |
| Degraded | Agent is operating with limitations |
| Maintenance | Agent is undergoing maintenance |
| Retired | Agent is no longer active |
| Archived | Agent identity is retained for history |

Status must be represented separately from the avatar.

# Versioning Policy

Use semantic versioning.

| Change Type | Example | Meaning |
|-------------|---------|---------|
| Major | 2.0.0 | Significant identity redesign |
| Minor | 1.1.0 | New approved variant or role badge |
| Patch | 1.0.1 | Small technical correction |

Operational configuration changes do not automatically require a visual identity version change.

---

# Agent Role Change

When an agent role changes:

- Review the display name.
- Review the role code.
- Review the department assignment.
- Review the role symbol.
- Review the agent ID policy.
- Update metadata.
- Generate updated exports where required.
- Archive superseded assets.
- Update all dependent interfaces.

A major role change may require a new agent identity instead of modifying the existing one.

---

# Department Transfer

When an agent transfers departments:

- Confirm new ownership.
- Update department metadata.
- Update accent token.
- Update team assignment.
- Review permissions.
- Update routing rules.
- Update dashboards.
- Archive the old identity version.
- Maintain audit history.

---

# Retirement Policy

When an agent is retired:

- Mark the agent identity as retired.
- Disable active usage.
- Record retirement reason.
- Record replacement agent where applicable.
- Update team directories.
- Update workflow assignments.
- Archive identity assets.
- Preserve audit records.

Retired agent identities must not be deleted.

---

# Duplicate Agent Prevention

Before creating a new identity, verify:

- Role does not already exist.
- Agent ID is unique.
- System name is unique.
- Role code is valid.
- Department assignment is correct.
- Similar capability agents have been reviewed.
- A reusable existing identity cannot satisfy the need.

# Bias and Representation Review

AI workforce identities must avoid:

- Gender stereotypes
- Racial stereotypes
- Cultural stereotypes
- Religious symbolism without purpose
- National stereotypes
- Occupational stereotypes
- Human superiority or inferiority signals
- Misleading emotional expressions

The preferred system should be neutral and role-based.

---

# Impersonation Prevention

AI identities must not:

- Copy a real employee's face.
- Imitate a public figure.
- Use a customer's identity.
- Suggest human employment status.
- Hide that the entity is an AI agent.
- Use credentials not present in governance records.

Interfaces should clearly label AI agents as AI.

---

# Accessibility

AI workforce identities should:

- Maintain sufficient contrast.
- Remain recognizable without color.
- Include text labels in critical workflows.
- Provide meaningful alternative text.
- Support zoom and high-resolution displays.
- Avoid flashing or animated identity effects.
- Use understandable status labels.

Recommended alternative text pattern:

```text
{Display Name}, Mianx.ai AI agent
```

Example:

```text
Backend Architect Agent, Mianx.ai AI agent
```

- [ ] Team assigned
- [ ] Role code approved

# Audit Requirements

AI workforce identity audits should verify:

- Agent ID uniqueness
- Current identity version
- Correct department assignment
- Correct team assignment
- Correct role code
- Approved avatar usage
- Unauthorized modifications
- Missing metadata
- Deprecated identity usage
- Retired agent visibility
- Public exposure permissions
- Source-file integrity
- Accessibility compliance

Recommended audit frequency:

```text
Monthly for active workforce registry

Quarterly for visual asset library
```

# Common Mistakes

Avoid:

- Designing every agent in a completely different style.
- Using photorealistic human faces.
- Making agents look like real employees.
- Embedding runtime status into master avatars.
- Using random colors for each agent.
- Creating duplicate agent IDs.
- Giving agents informal names.
- Publishing draft identities.
- Treating an AI team as a separate company brand.
- Storing avatars without metadata.
- Deleting retired identities.
- Displaying internal identifiers publicly without review.
- Using an avatar instead of a traceable Agent ID.

# Best Practices

- Build one reusable avatar component system.
- Keep department, role, and status layers separate.
- Make Agent IDs visible in critical workflows.
- Clearly label all agents as AI.
- Prefer abstract role-based identities.
- Keep visual complexity low.
- Synchronize assets with the agent registry.
- Preserve every released identity version.
- Audit active and retired identities regularly.
- Use automation to generate consistent exports.
- Keep brand, workforce, governance, and runtime records synchronized.
