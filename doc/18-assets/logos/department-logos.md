# Purpose

This document defines the official standards for department logos used throughout the Mianx.ai organization.

It ensures that every department has a clear and recognizable visual identity without creating separate or competing brands.

Department logos must remain subordinate to and visually connected with the primary Mianx.ai corporate identity.

---

# Objectives

- Standardize department logo creation.
- Maintain a unified enterprise identity.
- Prevent unnecessary sub-brands.
- Support department-specific communication.
- Improve asset discovery and reuse.
- Define approval and governance requirements.
- Preserve source files and version history.
- Enable compliant use by AI agents.

# Core Principle

The Mianx.ai corporate logo remains the primary brand.

A department identity may include:

- The official Mianx.ai logo
- Department name
- Approved department descriptor
- Approved department symbol where necessary
- Approved department accent token

A department must not create a separate company-style brand identity without executive and brand approval.

# Department Naming Standard

Department names must be:

- Officially approved
- Consistent with the organization structure
- Clear and unambiguous
- Free from temporary project terminology
- Registered in the department directory
- Written consistently across all assets

---

# Approved Naming Pattern

Preferred pattern:

```text
Mianx.ai [Department Name]
```

Examples:

```text
Mianx.ai Engineering

Mianx.ai Security

Mianx.ai Product

Mianx.ai Data & AI
```

Alternative lockup:

```text
[Corporate Logo] | [Department Name]
```

---

# Department Name Restrictions

Do not use:

- Unapproved abbreviations
- Informal nicknames
- Temporary team names
- Individual employee names
- Project code names
- Duplicate department names
- Misleading organizational titles

Example of incorrect naming:

```text
Super Dev Team

Marketing Ninjas

Security Heroes

New AI Group
```

---

# Department Hierarchy

Department identities must represent the organization hierarchy accurately.

Example:

```text
Engineering
│
├── Frontend
├── Backend
├── Mobile
├── Platform
└── DevOps
```

Sub-department identities must remain visually subordinate to the main department.

Example:

```text
Mianx.ai Engineering
Backend Team
```

# Department Symbols

Department symbols should use a shared visual language.

They must be:

- Simple
- Geometric
- Scalable
- Distinct
- Consistent
- Accessible
- Related to the department function

Avoid:

- Detailed illustrations
- Photographic symbols
- Unapproved emoji
- Clip art
- Random icon styles
- Symbols that resemble another company's logo

# Clear Space

Define a protected area around each department lockup.

Recommended unit:

```text
X = height of the corporate logo symbol
```

Minimum clear space:

```text
1 × X on all sides
```

No text, borders, icons, or graphics should enter the protected area.

---

# Minimum Size

Minimum size must be validated for each lockup.

Validation must confirm:

- Corporate logo visibility
- Department-name readability
- Separator visibility
- Small-screen behavior
- Print clarity

The approved minimum size must be recorded in asset metadata.

Example:

```text

├── CTO Agent
├── Architecture Agent
├── Backend Agent
├── Frontend Agent
└── DevOps Agent
```

Department branding and agent branding must remain separate.

The department identity represents the organizational function.

The agent identity represents an executable AI role.

# AI Usage Rules

AI agents may:

- Locate approved department assets.
- Select the correct variant.
- Add approved department lockups to documents.
- Validate department codes.
- Detect outdated assets.
- Report missing metadata.
- Apply approved department accent tokens.

AI agents must not:

- Invent new department logos.
- Change official colors.
- Modify symbols.
- Create unapproved department names.
- Publish draft assets.
- Bypass the approval workflow.
- Treat department badges as independent brands.

---

# File Naming Convention

Use lowercase kebab-case.

Pattern:

```text
{department-name}-{asset-type}-{variant}-{version}.{extension}
```

Examples:

```text
engineering-logo-horizontal-v1.svg

security-logo-dark-v1.svg

data-ai-department-badge-v1.svg

marketing-department-symbol-v1.svg

finance-logo-monochrome-v1.pdf
```

Avoid:

```text
engineering-final-logo.svg

new-security-logo.png

department-logo-latest.svg

marketing-logo-final-final.svg
```

---

# Versioning Policy

Use semantic versioning.

| Change Type | Example | Meaning |
|-------------|---------|---------|
| Major | 2.0.0 | Department reorganization or significant redesign |
| Minor | 1.1.0 | New approved variant or symbol |
| Patch | 1.0.1 | Small technical correction |

Released versions must never be overwritten.

# Department Reorganization

When departments are:

- Renamed
- Merged
- Split
- Transferred
- Closed
- Reclassified

The branding update must include:

- Organization approval
- Department directory update
- Logo migration plan
- Asset replacement
- Documentation update
- Workflow ownership update
- AI routing update
- Access-control review
- Archive process

---

# Deprecation Policy

When a department identity is retired:

- Mark it as deprecated.
- Record the reason.
- Identify the replacement department.
- Set a migration deadline.
- Notify affected teams.
- Update documentation.
- Update internal systems.
- Archive old assets.
- Preserve historical records.

Deprecated department assets must not be deleted.

# Legal and Licensing

Before publishing department assets, confirm:

- Font licensing
- Icon licensing
- Symbol originality
- Third-party asset permissions
- Partnership restrictions where applicable

---

# Accessibility

Department identities should:

- Maintain sufficient contrast.
- Remain readable at approved sizes.
- Avoid relying only on color.
- Include meaningful alternative text.
- Support zoomed interfaces.
- Remain recognizable in monochrome.

Recommended alternative text:

```text
Mianx.ai {Department Name}
```

Example:

```text
Mianx.ai Engineering
```

---

# Usage Rules

Always:

- Use approved department assets.
- Keep the corporate brand primary.
- Use the official department name.
- Use the current active version.
- Follow clear-space requirements.
- Use approved colors and typography.
- Link the asset to official metadata.

Never:

- Invent a department sub-brand.
- Recolor the corporate logo.
- Add unofficial slogans.
- Stretch or rotate the logo.
- Use unapproved abbreviations.
- Combine random icons with the logo.
- Publish draft variants.
- Use deprecated assets for new work.
- Present a department as a separate company.

# Common Mistakes

Avoid:

- Creating separate brands for every department.
- Giving departments unrelated visual identities.
- Using inconsistent department names.
- Creating duplicate department codes.
- Adding department names directly into the corporate master logo.
- Assigning random department colors.
