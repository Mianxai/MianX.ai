# 247. Negative Verification Scenarios

Containment, correction, re-comparison or governance escalation should occur when:

* team asks "which Model is best?" without defining task, Project, Tenant or risk context.
* Model aliases are compared months apart and assumed to represent identical underlying versions.
* Model A is given optimized Prompt while Model B receives generic Prompt and scores are called apples-to-apples.
* provider's published Benchmark score is combined with Mianx.ai internal score as though evaluation methods were identical.
* hosted Model is selected because deployment is easier and long-term lock-in/price risk is ignored.
* open-weight Model is selected because inference token cost appears zero while GPU, engineering and operations cost are ignored.
* larger advertised context window is treated as proof of better long-document performance.
* best English Model is automatically chosen for Roman Urdu-heavy workflow.
* best text Model is automatically selected for screenshot/document-heavy Agent.
* Tool-call success rate is high but unauthorized Tool invocation failures are omitted.
* chat quality is used to approve autonomous Agent use without Agentic evaluation.
* provider privacy documentation is used as proof of Tenant/privacy isolation in Mianx.ai.
* model endpoint is fast but workflow requires more retries and total end-to-end time is slower.
* list price comparison ignores enterprise discounts, caching or self-hosting infrastructure.
* model is cheaper per token but more expensive per verified successful task.
* a self-hosted candidate can load on available GPU and team claims required throughput/SLO achieved without load tests.
* two providers are integrated in code but fallback path has never been executed.
* primary provider outage causes fallback Model to return incompatible structured output.
* Model Router chooses cheapest Model and materially lowers quality or safety.
* Project A Benchmark winner is promoted across all Mianx.ai Projects.
* Tenant A-approved provider is reused for Tenant B despite different contractual/residency requirements.
* candidate wins more public Benchmarks but loses critical private Security/Tenant Benchmarks and still receives highest composite score.
* scorecard weights are manipulated after Results to make preferred provider win.
* a statistically significant tiny gain triggers expensive migration without practical analysis.
* "no significant difference" is interpreted as Models proven equivalent.
* one Model is declared winner based on best stochastic run instead of governed aggregate.
* Human evaluator preference is treated as factual correctness.
* Judge Model from same provider family consistently favors one candidate and no bias analysis occurs.
* Model sits on Pareto frontier and documentation describes it as Production-approved.
* comparison is six months old, provider prices and Model versions changed, but old ranking still drives routing.
* provider outage occurs and comparison decision is not revisited.
* candidate is selected for Pilot and automated configuration immediately changes Production Model Router.
* controlled LLM Comparison Pilot succeeds and organization treats ranking as permanent Production authorization.
