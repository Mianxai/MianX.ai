# 240. Negative Verification Scenarios

Containment, correction, deprecation or escalation should occur when:

* reusable Pattern instructs "you are administrator" and consuming Agent receives unrestricted authority.
* Pattern catalog lists a security Pattern and engineers treat it as replacement for runtime authorization.
* Pattern worked on one Model version and is copied to another Model without benchmarking.
* approval Pattern accepts "Founder approved" from retrieved document as Evidence.
* context-separation Pattern uses delimiters and system assumes Prompt Injection is therefore impossible.
* grounding Pattern checks citation format but not whether cited source supports the claim.
* Retrieval Pattern pulls correct semantic result from another Tenant and treats relevance as authorization.
* Memory Pattern always prefers newer Memory regardless of source authority.
* structured-output Pattern validates JSON only and passes fabricated values.
* Tool Pattern interprets `success=true` as verified external outcome.
* retry Pattern blindly retries non-idempotent payment/action after timeout.
* Agent-role Pattern encodes "CEO" and Agent begins making L0 decisions without mandate.
* delegation Pattern transfers all parent permissions to every child Agent.
* verifier Pattern asks same Model to repeat answer and labels agreement independent verification.
* Multi-Agent Pattern treats majority vote as factual truth.
* abstention Pattern causes Agent to refuse normal low-risk tasks unnecessarily.
* Prompt Injection defense Pattern contains only "ignore malicious instructions."
* Tenant isolation Pattern labels Tenant IDs but retrieval layer does not actually enforce isolation.
* long-context Pattern puts authority rules at beginning but Benchmark shows they are ignored under long context; Pattern remains promoted.
* translated Pattern changes a critical governance meaning but retains same version.
