# Mianx.ai Research Lab Knowledge Transfer — Best Practices

> **Research creates Evidence. Knowledge Transfer makes that Evidence useful without destroying its context, limitations, provenance or governance boundaries.**
>
> The preferred flow is:
>
> ```text
> RESEARCH
> ACTIVITY
>
> ↓
>
> OBSERVATIONS
>
> ↓
>
> EVIDENCE
>
> ↓
>
> CLAIMS
>
> ↓
>
> CONCLUSIONS
>
> ↓
>
> VALIDATED
> LESSONS
>
> ↓
>
> KNOWLEDGE
> PACKAGE
>
> ↓
>
> TARGETED
> TRANSFER
>
> ↓
>
> REUSE /
> APPLICATION
>
> ↓
>
> FEEDBACK /
> REVALIDATION
> ```
>
> The transfer process must not silently convert uncertain Research into absolute enterprise truth.

# 196. Negative Verification Scenarios

Containment, correction, revalidation or governance escalation should occur when:

* Research summary removes caveats to make Result appear stronger.
* raw Experiment logs are stored in Knowledge Base and labeled final Knowledge without analysis.
* a single observation is converted into enterprise-wide Best Practice.
* failed Experiment is deleted because it did not support desired hypothesis.
* negative Result is omitted from training because it is considered unhelpful.
* Research team calls an internal recommendation mandatory Standard without governance approval.
* reference Prototype is copied into Production and described as approved architecture.
* historical Model-specific lesson is applied after Model/provider changes without revalidation.
* Knowledge with strong confidence is interpreted by Agent as authorization to execute side-effecting Tools.
* contradictory Research findings exist but search ranking hides one.
* superseded Knowledge is silently deleted, breaking audit lineage.
* retracted Knowledge remains embedded in Agent Memory without downstream reconciliation.
* Project A performance lesson is applied to Project B despite different Data and workflow.
* Tenant A customer behavior findings are exposed to Tenant B.
* cross-Tenant lesson includes raw sensitive examples because team calls them "knowledge."
* Knowledge Base entry is treated as canonical policy merely because it ranks first in search.
* semantic search exposes metadata/content from restricted Tenant.
* Agent retrieves stale Founder approval from Memory and uses it as current authority.
* AI-generated summary invents a limitation or Result not supported by source Research.
* Agent A sends unsupported claim to Agent B, which treats it as trusted fact.
* external webpage contains malicious instruction and Knowledge pipeline imports it as executable policy.
* Research document includes API credential and Knowledge ingestion copies it into Memory.
* technical Research succeeds and ethical limitations are removed from transfer package.
* internal Research lesson is published externally before IP/privacy/security review.
* citation is present and team assumes copyright/license permission therefore exists.
* Product receives Research recommendation and records it as committed roadmap item.
* Engineering receives reference code and deploys it as Production-ready implementation.
* Security Research finding is transferred and dashboard reports issue fixed although remediation is not implemented.
* Knowledge is transferred successfully and system marks it adopted without verifying actual use.
* Agent retrieves Knowledge frequently and organization reports high Knowledge value despite poor task outcomes.
* controlled Knowledge Transfer Pilot succeeds and system enables unrestricted Production Agent retrieval without separate authorization.
