# Mianx.ai Research Lab Prototypes — Prototype Framework

> **A Prototype is a bounded Research artifact used to make an uncertainty testable.**
>
> It may represent, simulate, approximate or implement part of a future capability, but it does not itself prove that the future capability is complete, viable, secure, scalable or Production-ready.

# 3. Prototype Definition

For Mianx.ai:

> A Prototype is a deliberately bounded representation or implementation created to test a defined Research Question, design assumption, technical hypothesis, workflow, interaction, architecture or AI behavior before committing to larger-scale product or platform development.

# 220. Negative Verification Scenarios

Containment, correction, reclassification, invalidation, discard or escalation should occur when:

* a clickable interface Prototype is shown and team claims backend capability exists.
* one successful technical spike is described as Product viability.
* a disposable Prototype is copied directly into Production repository because it "already works."
* a Production-adjacent Prototype is treated as Production-ready without separate readiness review.
* high-fidelity mock is shown to customer without clarifying that key automation is simulated.
* a manually operated AI workflow is described as autonomous.
* mock external service always returns success and team concludes real integration is reliable.
* synthetic Tenant IDs are used in a shared Data store and team claims Tenant isolation is verified.
* Prototype uses real client Data without Project/Tenant rights review.
* Prompt says Agent is CEO and Prototype allows unrestricted enterprise actions.
* Multi-Agent system reaches consensus and result is labeled independently verified.
* Tool returns `success=true` and Prototype records business side effect complete without source-system read-back.
* Prototype sandbox has unrestricted network and Production secrets but is still treated as isolated.
* raw API credentials are stored in Prompt text for convenience.
* Prompt Injection Benchmark passes a few known attacks and Prototype is described as secure against Prompt Injection.
* Model provider version changes but Prototype Evidence remains combined under the old version.
* Prompt changes midway through experiment and outputs are compared as one configuration.
* Data quality problem causes poor output and team concludes underlying architecture is invalid without separating causes.
* positive demonstration cases are retained while failures are removed from report.
* Prototype is shown to a client and commercial team promises Production dates.
* Prototype code is transferred to Engineering and report says "Production implementation complete."
* archived Prototype from an older Model is reused without revalidation.
* Prototype Pilot succeeds and entire subsystem is called Production-ready.
* generated Prototype documentation is described as saved to repository without filesystem Evidence.
