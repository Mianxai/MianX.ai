# Mianx.ai Agent Compliance

> **This document defines how compliance obligations applicable to one
> individual Mianx.ai Agent are identified, mapped to controls,
> evidenced, tested, evaluated, remediated, reviewed, and governed.**
>
> Compliance is an assurance discipline.
>
> It is not a self-declaration mechanism.
>
> The permanent rule is:
>
> ```text
> AGENT SAYS
> "I AM COMPLIANT"
> ≠
> VERIFIED COMPLIANCE
> ```
>
> Likewise:
>
> ```text
> POLICY DOCUMENTED
> ≠
> CONTROL IMPLEMENTED
>
> CONTROL IMPLEMENTED
> ≠
> CONTROL OPERATING EFFECTIVELY
>
> CONTROL OPERATING ONCE
> ≠
> CONTROL OPERATING CONSISTENTLY
>
> EVIDENCE EXISTS
> ≠
> EVIDENCE SUFFICIENT
>
> DASHBOARD GREEN
> ≠
> COMPLIANCE PROVEN
>
> NO FINDING RECORDED
> ≠
> NO COMPLIANCE FAILURE
> ```
>
> Compliance must be supported by:
>
> ```text
> APPLICABLE OBLIGATION
> ↓
> CONTROL OBJECTIVE
> ↓
> CONTROL
> ↓
> IMPLEMENTATION
> ↓
> EVIDENCE
> ↓
> TEST
> ↓
> RESULT
> ↓
> FINDING / PASS
> ↓
> REMEDIATION IF NEEDED
> ↓
> RE-VERIFICATION
> ```
>
> Runtime compliance engines, automated control testing, attestation
> services, compliance dashboards, continuous-control monitoring,
> Project/Customer/Tenant compliance isolation, regulatory mappings, and
> Production compliance enforcement remain `NOT_PROVEN` unless actual
> implementation Evidence exists.

# 2. Agent Compliance Mission

The mission is:

> **Provide evidence-backed assurance that an individual Agent and its
> governed operating configuration satisfy all applicable enterprise,
> Security, Privacy, Data, contractual, regulatory, customer, Tenant,
> Project, environment, capability, Tool, Model, Memory, and operational
> obligations within the scope being assessed.**

```text

=
```

```text
=
```

# 6. Compliance vs Policy

```text
=
```

# 7. Compliance vs Security

Security controls may satisfy compliance obligations.

```text
SECURE
≠
COMPLIANT WITH EVERY OBLIGATION

COMPLIANT
≠
SECURE AGAINST EVERY THREAT
```

# 8. Compliance vs Audit
