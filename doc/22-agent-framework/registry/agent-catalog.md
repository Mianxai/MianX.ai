# Mianx.ai Agent Catalog

> **This document defines the governed descriptive catalog of Mianx.ai
> Agents and Agent Definitions.**
>
> The Agent Catalog should help an authorized Human, Agent, or system
> answer questions such as:
>
> ```text
> WHAT AGENT DEFINITIONS EXIST?
>
> WHAT IS EACH AGENT DESIGNED TO DO?
>
> WHAT TYPE OF AGENT IS IT?
>
> WHICH DEPARTMENT / ORGANIZATIONAL AREA
> DOES IT BELONG TO?
>
> WHICH CAPABILITIES
> DOES ITS DEFINITION REFERENCE?
>
> WHICH SKILLS
> DOES ITS DEFINITION REFERENCE?
>
> WHICH TASK CLASSES
> MAY IT SUPPORT?
>
> WHAT VERSION
> IS BEING DESCRIBED?
>
> WHAT LIFECYCLE STATUS
> MAY BE DISPLAYED?
>
> IS IT DEPRECATED?
>
> WHAT DOCUMENTATION
> DESCRIBES IT?
>
> WHO OWNS OR STEWARDS IT?
>
> IS THIS CATALOG VIEW CURRENT?
> ```
>
> It must never allow the caller to infer:
>
> ```text
> "I CAN SEE THIS AGENT,
> THEREFORE
> I MAY USE IT."
> ```
>
> Permanent rule:
>
> ```text
> CATALOG
> =
> DESCRIPTIVE
> DISCOVERY METADATA
>
> NOT
>
> REGISTRATION,
> ACTIVATION,
> ALLOCATION,
> ASSIGNMENT,
> AUTHORIZATION,
> OR
> EXECUTION.
> ```
>
> Runtime Catalog service, Registry synchronization, discovery indexing,
> caller-scoped catalog views, metadata redaction, freshness guarantees,
> Project/Customer/Tenant isolation, search ranking, and Production
> operation remain `NOT_PROVEN` unless implementation Evidence exists.

# 2. Agent Catalog Mission

The mission is:

> **Provide a governed, searchable, understandable, scope-aware view of
> Mianx.ai Agent Definitions so authorized Humans and systems can
> understand what Agents exist and what they are designed for without
> confusing descriptive metadata with live registration, runtime
> availability, assignment, health, authorization, or Production
> readiness.**

# 5. What Is an Agent Catalog?

The Agent Catalog is:

> **A governed descriptive view of Agent Definitions and approved
> metadata designed for Human and machine understanding, browsing,
> search, filtering, documentation lookup, and discovery support.**

---

# 6. What the Agent Catalog Is Not

The Catalog is not:

```text
THE AUTHORITATIVE AGENT RUNTIME

AN ACTIVATION SERVICE

AN ASSIGNMENT QUEUE

A PERMISSION STORE

A SECRET STORE

A PROMPT STORE

A CREDENTIAL STORE

A HEALTH SOURCE OF TRUTH

AN AGENT EXECUTION API

A GUARANTEE OF AVAILABILITY

A GUARANTEE OF PRODUCTION READINESS
```

---

# 7. Catalog vs Agent Definition

An Agent Definition describes what an Agent is designed to be.

A Catalog entry is a governed projection of selected Definition metadata.

```text
AGENT DEFINITION
≠
CATALOG ENTRY
```

---

# 8. Catalog Projection Boundary

The Catalog should not necessarily expose every field from the Agent
Definition.

Sensitive or unnecessary metadata may be excluded.

---

# 9. Catalog vs Agent Instance

```text
CATALOG ENTRY
≠
AGENT INSTANCE
```

The Catalog may describe a Definition even when no live instance exists.

---

# 10. Catalog vs Agent Run

```text
CATALOG ENTRY
≠
AGENT RUN
```

---

# 11. Catalog vs Registry

The Agent Registry is intended to govern authoritative registration
state and identity relationships.

The Catalog provides a descriptive view.

Permanent boundary:

```text
CATALOG VIEW
≠
AUTHORITATIVE REGISTRATION STATE
```

See:

```text
./agent-registry.md
```

---

# 12. Catalog vs Discovery

The Catalog exposes descriptive searchable metadata.

Agent Discovery defines how an authorized caller searches for or
identifies candidate Agents.

```text
CATALOG
=
SEARCHABLE DESCRIPTIVE DATA

DISCOVERY
=
GOVERNED CANDIDATE-FINDING PROCESS
```

See:

```text
./agent-discovery.md
```

---

# 13. Catalog vs Agent Router

Even if Discovery returns an Agent candidate:

```text
DISCOVERED
≠
ROUTED

ROUTED
≠
ASSIGNED

ASSIGNED
≠
AUTHORIZED
```
