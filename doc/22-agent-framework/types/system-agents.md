# Mianx.ai System Agents

> **This document defines the System Agent Type within the Mianx.ai
> individual-Agent Framework.**
>
> System Agents exist to perform bounded machine-oriented work that
> supports platform and Agent operations.
>
> Their potential responsibility areas include:
>
> ```text
> RUNTIME SUPPORT
>
> SCHEDULING SUPPORT
>
> ROUTING SUPPORT
>
> HEALTH OBSERVATION
>
> MONITORING
>
> SYNCHRONIZATION
>
> MAINTENANCE
>
> RECOVERY COORDINATION
>
> AUDIT SUPPORT
>
> POLICY-ENFORCEMENT SUPPORT
>
> INFRASTRUCTURE-FACING OPERATIONS
>
> CONTROL-PLANE SUPPORT
> ```
>
> They must never be interpreted as:
>
> ```text
> THE AI OPERATING SYSTEM ITSELF
>
> THE MASTER ORCHESTRATOR ITSELF
>
> PLATFORM ROOT
>
> GLOBAL ADMINISTRATORS
>
> UNIVERSAL SERVICE ACCOUNTS
>
> SECRET VAULT OWNERS
>
> CROSS-TENANT SUPERUSERS
>
> BREAK-GLASS PRINCIPALS
>
> UNRESTRICTED PRODUCTION OPERATORS
> ```
>
> Permanent rule:
>
> ```text
> SYSTEM AGENT
> =
> MACHINE-ORIENTED
> GOVERNED
> SYSTEM SUPPORT
> AGENT TYPE
>
> NOT
>
> PLATFORM ROOT
> AUTHORITY.
> ```

# 2. System Agent Mission

The mission is:

> **Provide narrowly scoped, auditable, machine-oriented support for
> runtime, monitoring, routing, scheduling, synchronization,
> maintenance, recovery and control-plane operations without converting
> platform proximity, background execution, machine identity or
> infrastructure visibility into unrestricted administrative or
> Production authority.**

# 5. What Is a System Agent?

A System Agent is:

> **An individual-Agent Type designed to perform bounded operational,
> platform-facing or runtime-support work on behalf of the Mianx.ai
> system under explicit machine identity, security, Tool, scope,
> environment and authorization controls.**

---

# 15. System Agent vs Service

Traditional platform services may be deterministic software.

A System Agent is an Agent Definition using the Agent Framework.

```text
SYSTEM SERVICE
≠
SYSTEM AGENT
```

---

# 16. Service Boundary

A deterministic health checker does not need to be reclassified as an
Agent merely because it runs automatically.

---

# 17. Agent Necessity Rule

Use a System Agent only where Agent-like:

```text
REASONING

INTERPRETATION

ADAPTIVE PLANNING

BOUNDED DECISION SUPPORT

CONTEXTUAL ANALYSIS
```

is justified.

Do not replace simple deterministic controls with unnecessary Agent
reasoning.
