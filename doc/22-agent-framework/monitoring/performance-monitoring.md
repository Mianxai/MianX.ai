# Mianx.ai Agent Performance Monitoring

> **This document defines how the runtime and historical performance of
> an individual Mianx.ai Agent is observed without converting activity,
> latency, throughput, cost, utilization, self-reported completion, or
> dashboard scores into false claims of quality, value, authority, or
> Production fitness.**
>
> Permanent rule:
>
> ```text
> PERFORMANCE
> =
> CONTEXTUAL,
> OUTCOME-AWARE,
> RISK-AWARE,
> EVIDENCE-AWARE
> OBSERVATION
>
> NOT
>
> A SINGLE NUMBER
> ```
>
> Therefore:
>
> ```text
> ACTIVITY
> ≠
> PERFORMANCE
>
> BUSY
> ≠
> PRODUCTIVE
>
> TASK COMPLETED
> ≠
> TASK VERIFIED
>
> HIGH THROUGHPUT
> ≠
> HIGH VALUE
>
> LOW LATENCY
> ≠
> HIGH QUALITY
>
> LOW COST
> ≠
> GOOD PERFORMANCE
>
> HIGH UTILIZATION
> ≠
> HEALTHY CAPACITY
>
> FEWER ESCALATIONS
> ≠
> BETTER AUTONOMY
>
> METRIC IMPROVEMENT
> ≠
> PRODUCTION AUTHORIZATION
> ```
>
> Performance telemetry, Verified Success calculation, attribution,
> regression detection, cost accounting, trend detection, Project /
> Customer / Tenant segmentation, alerting, Production dashboards, and
> Production performance gates remain `NOT_PROVEN` unless implementation
> Evidence exists.

# 2. Performance Monitoring Mission

The mission is:

> **Provide trustworthy, context-aware visibility into how an
> individual Mianx.ai Agent performs over time so that Humans and
> governed systems can identify quality degradation, reliability
> problems, inefficient execution, excessive cost, unsafe behavior,
> regressions, and improvement opportunities without optimizing the
> Agent toward misleading proxy metrics.**

# 5. Performance Monitoring vs Performance Evaluation

Performance Monitoring observes runtime and historical operating
signals continuously or periodically.

Performance Evaluation provides governed interpretation and formal
evaluation.

```text
MONITORING DATA
≠
FINAL EVALUATION
```

See:

```text
../evaluation/performance-evaluation.md
```

---

# 6. Performance Monitoring vs Benchmarking

Benchmarking measures Agent behavior under defined benchmark conditions.

Performance Monitoring observes actual runtime behavior.

```text
BENCHMARK PERFORMANCE
≠
LIVE PERFORMANCE
```

---

# 7. Performance Monitoring vs Health Monitoring

Health Monitoring asks:

```text
CAN THIS AGENT
CURRENTLY OPERATE?
```

Performance Monitoring asks:

```text
HOW WELL
HAS THIS AGENT
BEEN OPERATING?
```

Therefore:

```text
HEALTHY
≠
HIGH PERFORMING

LOW PERFORMING
≠
UNHEALTHY
```

---

# 8. Performance Monitoring vs Audit

Audit preserves attributable historical events.

Performance Monitoring derives operational measurements and trends.

```text
AUDIT EVENT
≠
PERFORMANCE METRIC
```

```text
AGENT V1 PERFORMANCE
```

```text
PROJECT A PERFORMANCE
≠

```

# 12. Run Attribution

One Run is one attempt.

A Task may have multiple Runs.

```text
TASK
≠
RUN
```

---

Performance should be compared within meaningful Task classes.

```text

≠

```
