# Mianx.ai Agent Retirement

> **This document defines the governed process through which an
> individual Mianx.ai Agent, Agent Version, or Agent Allocation is
> safely withdrawn from normal future operation while preserving
> required enterprise history, Evidence, Audit, Knowledge, Memory
> ownership, dependency continuity, and security boundaries.**
>
> The permanent rule is:
>
> ```text
> RETIREMENT
> =
> OPERATIONAL WITHDRAWAL
> +
> AUTHORITY REVOCATION
> +
> DEPENDENCY HANDOFF
> +
> HISTORICAL PRESERVATION
>
> NOT
>
> DELETE EVERYTHING
> ```
>
> Therefore:
>
> ```text
> DEACTIVATED
> ≠
> RETIRED
>
> DEPRECATED
> ≠
> RETIRED
>
> RETIRED
> ≠
> DELETED
>
> RETIREMENT REQUESTED
> ≠
> RETIREMENT APPROVED
>
> RETIREMENT APPROVED
> ≠
> RETIREMENT COMPLETE
>
> PROCESS STOPPED
> ≠
> ALL EXTERNAL SIDE EFFECTS RECONCILED
>
> CREDENTIAL REVOKED
> ≠
> ALL ACTIVE SESSIONS TERMINATED PROVEN
>
> REPLACEMENT EXISTS
> ≠
> REPLACEMENT READY
>
> MEMORY NO LONGER USED BY AGENT
> ≠
> MEMORY SHOULD BE DELETED
>
> RETIRED
> ≠
> AUDIT HISTORY ERASED
> ```
>
> Runtime retirement controllers, work-drain engines, dependency
> migration, credential revocation, event-subscription cleanup,
> scheduled-job cleanup, Memory ownership transfer, Registry retirement
> enforcement, unauthorized-reactivation prevention, and Production
> retirement remain `NOT_PROVEN` unless actual implementation Evidence
> exists.

# 2. Agent Retirement Mission

The mission is:

> **Remove an Agent safely from future operational authority without
> losing the enterprise knowledge, lineage, Evidence, Audit history,
> accountability, dependency continuity, or historical truth required
> to understand what the Agent was, what it did, and why it was
> retired.**

↓

# 5. Retirement Object

Retirement may apply to different objects.

Potential subjects:

```text
AGENT DEFINITION

AGENT VERSION

AGENT ALLOCATION

RUNTIME INSTANCE
```

These must not be conflated.

---

# 6. Definition Retirement

Retiring an Agent Definition normally means the identity should no longer
be used for new normal operational Versions or Allocations.

---

# 7. Version Retirement

One Version may retire while Agent Definition continues with newer
Versions.

---

# 8. Allocation Retirement

One Project/Customer/Tenant Allocation may retire while other Allocations
remain active.

---

# 9. Runtime Instance Termination

Stopping one runtime Instance is not Agent Retirement.

```text
INSTANCE STOPPED
≠
AGENT RETIRED
```

---

# 10. Retirement Scope Boundary

```text
VERSION RETIRED
≠
ALL AGENT VERSIONS RETIRED

ALLOCATION RETIRED
≠
AGENT DEFINITION RETIRED

INSTANCE STOPPED
≠
ALLOCATION RETIRED
```

---

# 11. Retirement vs Deactivation

Deactivation removes Agent from current Active operation.

Retirement prevents normal future operational use.

```text
DEACTIVATED
≠
RETIRED
```

---

# 12. Retirement vs Suspension

Suspension is temporary or investigative restriction.

```text
SUSPENDED
≠
RETIRED
```

---

# 13. Retirement vs Deprecation

Deprecation discourages or restricts future use while migration proceeds.

```text
DEPRECATED
≠
RETIRED
```

---

# 14. Retirement vs Deletion

```text
RETIREMENT
≠
DELETE AGENT
```

Required identity, lineage, Evidence, Audit, and Knowledge may need to
remain.

---

# 15. Retirement vs Archival

Retirement is operational lifecycle state.

Archival is historical storage/retention treatment.

```text
RETIRED
≠
ARCHIVED
```

---

# 16. Retirement vs Replacement

```text
REPLACEMENT CREATED
≠
OLD AGENT RETIREMENT COMPLETE
```

---
