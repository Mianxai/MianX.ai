# Mianx.ai Agent Creation

> **This document defines how a new individual Mianx.ai Agent is
> proposed, justified, uniquely identified, designed, scoped,
> configured, validated, and prepared for governed registration and
> later activation.**
>
> Agent Creation creates a governed **Agent Definition** and normally an
> initial **Agent Version**.
>
> It does not create unrestricted runtime authority.
>
> Permanent rule:
>
> ```text
> AGENT CREATION
> =
> DEFINITION OF
> WHAT AN AGENT
> IS INTENDED TO BE
>
> NOT
>
> AUTOMATIC AUTHORIZATION
> TO OPERATE
> ```
>
> Therefore:
>
> ```text
> CREATED
> ≠
> REGISTERED
>
> REGISTERED
> ≠
> APPROVED
>
> APPROVED
> ≠
> ALLOCATED
>
> ALLOCATED
> ≠
> ACTIVE
>
> ACTIVE
> ≠
> PRODUCTION AUTHORIZED
> ```
>
> Runtime Agent factories, automated Agent-generation services,
> Definition registries, duplicate detection, template engines,
> validation pipelines, governance approvals, automatic Registry
> writes, and Production creation workflows remain `NOT_PROVEN` unless
> implementation Evidence exists.

# 2. Agent Creation Mission

The mission is:

> **Create the smallest, clearest, safest, uniquely identifiable Agent
> Definition needed to fulfill a legitimate organizational purpose,
> while explicitly defining its scope and constraints before any
> runtime activation is considered.**

# 5. Agent Creation vs Agent Generation

```text
GENERATION
=
MAY PRODUCE CONTENT

CREATION
=
GOVERNED ENTERPRISE PROCESS
THAT MAY ACCEPT,
REJECT,
OR REVISE
THAT CONTENT
```

A Model generating an Agent specification does not mean a governed
Agent has been created.

---

# 6. Agent Creation vs Registration

Creation defines the Agent.

Registration records the governed Agent identity/version in the
Registry.

```text
CREATED DEFINITION
≠
REGISTERED AGENT
```

---

# 7. Agent Creation vs Activation

Creation is pre-runtime.

Activation determines whether an eligible Version may become active.

```text
CREATED
≠
ACTIVE
```

# 11. Valid Need Examples

Potential:

```text
UNFILLED BUSINESS RESPONSIBILITY

SPECIALIZED DOMAIN WORK

UNACCEPTABLE WORKLOAD CONCENTRATION

REQUIRED SEGREGATION OF DUTIES

PROJECT-SPECIFIC ROLE

CUSTOMER-SPECIFIC ROLE

SPECIALIZED SECURITY BOUNDARY

NEW REPEATABLE TASK CLASS
```

---

# 12. Invalid Need Patterns

Avoid creating a new Agent merely because:

```text
A NEW MODEL EXISTS

A NEW TOOL EXISTS

A NEW PROMPT WAS WRITTEN

A ONE-OFF TASK EXISTS

A DIFFERENT DISPLAY NAME IS DESIRED

AN EXISTING AGENT COULD ALREADY HANDLE THE RESPONSIBILITY
```

---

# 13. Need Statement

Every proposed Agent should have an explicit need statement.

---

# 14. Need Statement Questions

```text
WHAT ORGANIZATIONAL PROBLEM EXISTS?

WHY IS AN AGENT NEEDED?

WHY CAN EXISTING AGENTS NOT HANDLE IT?

WHAT TASK CLASSES ARE INVOLVED?

WHAT VALUE DOES THE AGENT CREATE?

WHAT RISK DOES THE AGENT INTRODUCE?

WHAT HAPPENS IF THE AGENT IS NOT CREATED?
```

