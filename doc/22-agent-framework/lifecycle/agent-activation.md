# Mianx.ai Agent Activation

> **This document defines the governed transition through which an
> eligible Agent Definition and Agent Version may become a bounded
> runtime Agent Instance capable of participating in authorized work.**
>
> Activation is a security-sensitive lifecycle transition.
>
> It is not a convenience flag.
>
> The permanent rule is:
>
> ```text
> REGISTERED
> ≠
> ACTIVE
>
> APPROVED
> ≠
> ACTIVE
>
> CONFIGURED
> ≠
> ACTIVE
>
> DEPLOYABLE
> ≠
> ACTIVE
>
> INSTANCE CREATED
> ≠
> EXECUTION AUTHORIZED
>
> ACTIVE
> ≠
> AUTHORIZED FOR EVERY TASK
>
> ACTIVE
> ≠
> PRODUCTION AUTHORIZED
> ```
>
> Correct lifecycle transition:
>
> ```text
> AGENT DEFINITION
> ↓
> VERSION
> ↓
> GOVERNANCE REVIEW
> ↓
> REGISTRY ELIGIBILITY
> ↓
> ALLOCATION
> ↓
> SCOPE BINDING
> ↓
> SECURITY / POLICY VALIDATION
> ↓
> CAPABILITY / TOOL / MODEL / MEMORY VALIDATION
> ↓
> EVALUATION EVIDENCE
> ↓
> ACTIVATION APPROVAL
> ↓
> RUNTIME INSTANCE
> ↓
> STARTUP VALIDATION
> ↓
> ACTIVE
> ↓
> TASK-SPECIFIC AUTHORIZATION
> ```
>
> For Production:
>
> ```text
> ACTIVE
> ↓
> PRODUCTION-SPECIFIC GATES
> ↓
> EXPLICIT PRODUCTION AUTHORIZATION
> ↓
> CONTROLLED PRODUCTION OPERATION
> ```
>
> Runtime activation services, Allocation management, Activation
> Controller, policy enforcement, runtime instance identity,
> startup-health validation, Project/Customer/Tenant isolation,
> suspension, reactivation, revocation, emergency shutdown, and
> Production activation remain `NOT_PROVEN` unless implementation
> Evidence exists.

# 2. Agent Activation Mission

The mission is:

> **Ensure that only the exact approved Agent Version, operating within
> an explicitly authorized Allocation, Project, Customer, Tenant,
> environment, Capability, Tool, Model, Memory, autonomy, budget, and
> Security envelope, may become an active runtime Agent Instance.**

# 5. Activation vs Registration

```text
REGISTRATION
=
AGENT IS KNOWN
TO THE GOVERNED SYSTEM

ACTIVATION
=
AGENT INSTANCE IS PERMITTED
TO ENTER ACTIVE RUNTIME STATE
```

Therefore:

```text
REGISTERED
≠
ACTIVE
```

---

# 6. Activation vs Approval

An Agent Version may be approved as an artifact without being approved
for a particular runtime Allocation.

```text
VERSION APPROVED
≠
ALLOCATION APPROVED
```

---

# 7. Activation vs Deployment

Software may be technically deployed while Agent remains inactive.

```text
CODE DEPLOYED
≠
AGENT ACTIVATED
```

---

# 8. Activation vs Execution Authorization

Activation establishes runtime eligibility.

It does not authorize every later action.

```text
ACTIVE
≠
EVERY ACTION AUTHORIZED
```

---

# 9. Activation vs Production Authorization

```text
ACTIVE IN TEST
≠
PRODUCTION AUTHORIZED

ACTIVE IN STAGING
≠
PRODUCTION AUTHORIZED
```
