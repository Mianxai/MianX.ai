# Mianx.ai Agent Tool Registry

> **This document defines the governed control-plane registry for Tools
> known to the Mianx.ai Agent Framework.**
>
> The Tool Registry should answer:
>
> ```text
> WHAT TOOL EXISTS?
>
> WHAT IS ITS
> STABLE TOOL ID?
>
> WHAT VERSION?
>
> WHO PROVIDES IT?
>
> WHAT INTEGRATION
> INSTANCE EXISTS?
>
> WHAT OPERATIONS
> DOES IT EXPOSE?
>
> WHAT INPUT
> CONTRACTS EXIST?
>
> WHAT OUTPUT
> CONTRACTS EXIST?
>
> WHAT RESOURCES
> CAN IT TARGET?
>
> WHAT SIDE EFFECTS
> CAN OPERATIONS CAUSE?
>
> WHAT AUTHENTICATION
> DOES IT REQUIRE?
>
> WHAT CREDENTIAL
> REFERENCE TYPE
> DOES IT REQUIRE?
>
> WHAT DATA
> MAY FLOW THROUGH IT?
>
> WHAT RISK CLASS?
>
> WHAT ENVIRONMENTS
> MAY IT SUPPORT?
>
> WHAT PROJECT /
> CUSTOMER /
> TENANT
> APPLICABILITY EXISTS?
>
> WHAT HEALTH /
> COMPATIBILITY
> METADATA EXISTS?
>
> WHAT LIFECYCLE
> STATE IS CURRENT?
>
> WHO OWNS IT?
>
> WHAT IS
> ITS PROVENANCE?
>
> IS THIS RECORD
> CURRENT,
> INTEGRITY-CHECKED,
> AND GOVERNED?
> ```
>
> It must never conclude:
>
> ```text
> "THE TOOL IS REGISTERED,
> THEREFORE
> AN AGENT
> MAY USE IT."
> ```
>
> Permanent rule:
>
> ```text
> TOOL REGISTRY
> =
> CONTROL-PLANE
> TOOL METADATA
> AND IDENTITY
>
> NOT
>
> AGENT TOOL
> AUTHORIZATION.
> ```

# 2. Tool Registry Mission

The mission is:

> **Provide one governed, stable, version-aware and auditable source of
> Tool metadata so the Agent Framework can consistently identify what
> Tools and Tool Versions are known, what operations and resources they
> expose, what Security and risk characteristics apply, what
> integration instances exist, and what lifecycle state is current,
> without treating Registry presence as Agent permission, execution
> authority, health proof, availability proof, or Production
> authorization.**
