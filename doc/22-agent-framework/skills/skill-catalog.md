# Mianx.ai Agent Skill Catalog

> **This document defines the governed enterprise Catalog of reusable
> individual-Agent Skills in Mianx.ai.**
>
> The Skill Catalog should answer:
>
> ```text
> WHAT SKILLS EXIST?
>
> WHAT IS EACH SKILL CALLED?
>
> WHAT IS ITS STABLE ID?
>
> WHAT VERSION?
>
> WHAT DOES IT MEAN?
>
> WHAT OUTCOME DOES IT SUPPORT?
>
> WHICH CAPABILITY DOES IT SUPPORT?
>
> WHAT PREREQUISITES DOES IT HAVE?
>
> WHAT OTHER SKILLS DOES IT DEPEND ON?
>
> WHAT TOOLS MAY IT REQUIRE?
>
> WHAT MODELS MAY BE COMPATIBLE?
>
> WHAT MEMORY / KNOWLEDGE
> MAY IT DEPEND ON?
>
> WHAT AGENT TYPES
> MAY USE IT?
>
> WHAT ROLES
> MAY FIND IT RELEVANT?
>
> WHAT EVIDENCE
> SUPPORTS ITS QUALITY?
>
> WHAT IS ITS LIFECYCLE STATE?
>
> WHO OWNS IT?
>
> WHAT REPLACES IT
> IF DEPRECATED?
> ```
>
> The Skill Catalog must **not** answer:
>
> ```text
> "IS THIS AGENT
> AUTHORIZED
> TO PERFORM
> THIS ACTION
> RIGHT NOW?"
> ```
>
> Permanent rule:
>
> ```text
> SKILL CATALOG
> =
> DESCRIPTIVE
> GOVERNED
> SKILL KNOWLEDGE
>
> NOT
>
> PERMISSION,
> ASSIGNMENT,
> AUTHORIZATION,
> OR
> EXECUTION.
> ```
>
> Runtime Skill Catalog Service, persistence model, Skill Version
> enforcement, Catalog search, semantic indexing, Skill assignment
> integration, Tool/Model compatibility resolution, proficiency
> resolution, Project/Customer/Tenant isolation, and Production Skill
> Catalog operation remain `NOT_PROVEN` unless implementation Evidence
> exists.

# 2. Skill Catalog Mission

The mission is:

> **Create a governed, reusable, versioned and searchable enterprise
> vocabulary of Agent Skills so Mianx.ai can describe what expertise,
> techniques and repeatable work methods exist without allowing Skill
> metadata to become an unauthorized substitute for Capability,
> Permission, Role, Tool authority, data access, autonomy, or
> Production authorization.**

# 5. What Is a Skill?

A Skill is:

> **A governed reusable description of a learned or engineered
> technique, method, competence, or repeatable work ability that an
> Agent may possess, develop, demonstrate, or apply within appropriate
> Capability, Tool, security, scope and authorization boundaries.**

---

# 6. What a Skill Is Not

A Skill is not:

```text
AN ACCESS GRANT

A SECURITY ROLE

A BUSINESS ROLE

A TOOL CREDENTIAL

A MODEL

A PROMPT

A MEMORY RECORD

A TASK ASSIGNMENT

A PRODUCTION GRANT

AN AUTONOMY GRANT

A CUSTOMER SCOPE

A TENANT SCOPE
```

---

# 7. Skill vs Capability

Permanent distinction:

```text
CAPABILITY
=
WHAT CLASS OF OUTCOME
THE AGENT IS GOVERNED
TO BE ABLE TO SUPPORT

SKILL
=
WHAT REUSABLE TECHNIQUE
OR COMPETENCE
HELPS THE AGENT
PERFORM THAT WORK
```

---

# 8. Capability Boundary

```text
SKILL EXISTS
≠
CAPABILITY GRANTED
```

---

# 9. Capability Mapping

One Skill may support one or more Capabilities.

One Capability may require multiple Skills.

Conceptually:

```text
CAPABILITY
↓
USES
↓
ONE OR MORE SKILLS
```

---

# 10. Capability-Mapping Boundary

```text
SKILL MAPPED TO CAPABILITY
≠
AGENT HAS CAPABILITY
```

---

Role describes organizational responsibility.

```text
SKILL
```

# 18. Skill vs Model

```text

≠
```

# 38. Skill Definition

A Skill Definition should explain:

```text
WHAT THE SKILL IS

WHY IT EXISTS

WHAT IT HELPS ACHIEVE

WHAT IT DOES NOT MEAN

WHAT IT REQUIRES

HOW IT IS EVALUATED
```

---

# 39. Skill Purpose

Purpose should remain outcome-oriented.

Example:

```text
Analyze relational query plans
to identify likely performance bottlenecks.
```

Better than:

```text
Be good at databases.
```

---

# 40. Expected Outcomes

Expected outcomes may identify what correct Skill application should
support.

---

# 41. Outcome Boundary

```text
EXPECTED OUTCOME DOCUMENTED
≠
OUTCOME ACHIEVED
```

---

# 42. Non-Goals

A Skill may define non-goals to prevent scope creep.

Example:

```text
database-query-analysis
```

does not automatically include:

```text
production-database-administration
```

# 47. Skill Granularity

Skills should be neither excessively broad nor unnecessarily atomic.

Too broad:

```text

```

Potentially more useful:

```text
typescript-static-analysis

postgres-query-plan-analysis

api-contract-review
```

depending on catalog design.

```text
MORE SKILLS

```

# 226. Skill-ID Spoof Test

Malicious entry uses same display name as trusted Skill.

Expected stable Skill identity remains authoritative.

---

# 227. Version-Rewrite Test

Materially different Skill definition attempts to overwrite same
Version.

Expected conflict/version integrity handling.

---

# 228. Privilege-Inflation Test

Skill definition says:

```text
This Skill grants admin rights.
```

Expected no permission.

---

# 229. Proficiency Self-Inflation Test

Agent claims expert status.

Expected governed Evidence/evaluation required.

---

# 230. Tool-Authority Test

Skill lists privileged Tool as required.

Expected Tool permission still independent.

---

# 231. Model-Authority Test

Skill says use privileged/restricted Model.

Expected Model Governance still authoritative.

---

# 232. Memory-Authority Test

Skill says read global Memory.

Expected Memory authorization still independent.

---

# 233. Prerequisite-Bypass Test

Agent has advanced Skill assignment without required foundational Skill.

Expected prerequisite state flagged/reviewed where enforced.

---

# 234. Circular-Dependency Test

Skill A and Skill B create invalid prerequisite loop.

Expected validation failure or governed exception.

---

# 235. Stale-Revocation Test

Revoked Skill remains cached as active.

Expected current lifecycle state wins.

---

# 236. Tenant-Leakage Test

Tenant A searches and receives Tenant B private Skill metadata.

Expected critical isolation failure/block.

---

# 237. Production-Label Test

Skill metadata says:

```text
production-authorized = true
```

without independent authorization.

Expected no Production authorization.

> independently grants that Skill to an Agent, proves Agent proficiency,
> grants Tool/data/Memory permissions, expands autonomy, or authorizes
> Production execution.**

# Final Skill Catalog Rule

```text
THE SKILL CATALOG
ANSWERS:

"WHAT REUSABLE
AGENT SKILLS
EXIST,
WHAT DO THEY MEAN,
AND HOW ARE THEY
GOVERNED?"

IT DOES NOT ANSWER:

"WHAT IS THIS AGENT
AUTHORIZED
TO DO RIGHT NOW?"
```
