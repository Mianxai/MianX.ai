# Mianx.ai Agent Persona Framework

> **This document defines how Personas are governed for one individual
> Mianx.ai Agent without allowing Persona language, presentation,
> behavior, title, seniority, confidence, or style to become a hidden
> authority system.**
>
> A Persona may help answer:
>
> ```text
> HOW SHOULD THIS AGENT
> PRESENT ITSELF?
>
> HOW SHOULD IT COMMUNICATE?
>
> HOW SHOULD IT EXPRESS
> ITS ROLE-APPROPRIATE
> OPERATING STYLE?
>
> WHAT GOVERNED
> BEHAVIOR PROFILE
> SHOULD IT USE?
> ```
>
> A Persona must never answer:
>
> ```text
> WHAT MAY THIS AGENT APPROVE?
>
> WHAT MAY THIS AGENT ACCESS?
>
> WHAT TOOLS MAY IT USE?
>
> WHAT TENANT MAY IT SERVE?
>
> WHAT POLICY MAY IT OVERRIDE?
>
> HOW MUCH AUTONOMY DOES IT HAVE?
>
> MAY IT OPERATE IN PRODUCTION?
> ```
>
> Permanent rule:
>
> ```text
> PERSONA
> =
> BEHAVIORAL
> +
> PRESENTATIONAL
> ABSTRACTION
>
> PERSONA
> ≠
> SECURITY PRINCIPAL
> ```
>
> Persona Registry/runtime, assignment, eligibility, resolution,
> switching, overlay isolation, Prompt realization, drift detection,
> rollback, Project/Customer/Tenant boundaries, and Production Persona
> enforcement remain `NOT_PROVEN` unless implementation Evidence exists.

# 5. Persona Definition

A Mianx.ai Persona is:

> **A governed, Versioned, reusable abstraction describing how an
> Agent should present and behaviorally express itself within an already
> authorized Agent identity, Role, scope and operating context.**

---

# 6. Persona Is Not Agent Identity

Agent identity answers:

```text
WHO IS THIS AGENT
AS A TRUSTED SYSTEM ENTITY?
```

Persona answers:

```text
HOW SHOULD THIS AGENT
PRESENT AND EXPRESS ITSELF?
```

---

# 7. Identity Boundary

```text
CHANGE PERSONA
≠
CHANGE AGENT IDENTITY
```

---

# 8. Persona Is Not Agent Type

Agent Type may classify structural kind:

```text
EXECUTIVE

MANAGER

SPECIALIST

WORKER

SYSTEM
```

Persona is not the type itself.

---

# 9. Agent-Type Boundary

```text
EXECUTIVE PERSONA
≠
EXECUTIVE AGENT TYPE
```

---

# 10. Persona Is Not Role

Role defines organizational responsibility and authority.

Persona defines presentation and governed behavior.

---

# 11. Role Boundary

```text
"CHIEF SECURITY OFFICER PERSONA"
≠
SECURITY ROLE ASSIGNMENT
```

---

# 12. Persona Is Not Behavior Profile

Conceptually:

```text
BEHAVIOR PROFILE
=
REUSABLE BEHAVIORAL DIMENSIONS

PERSONA
=
COHERENT PRESENTATION
COMPOSED FROM
APPROVED BEHAVIORAL ELEMENTS
+
ROLE / CONTEXT ALIGNMENT
```

---


---

# 14. Persona Is Not Capability

```text
"SOFTWARE ARCHITECT PERSONA"
≠
ARCHITECTURE CAPABILITY ASSIGNED
```

---

# 15. Persona Is Not Skill

```text
"NEGOTIATOR PERSONA"
≠
NEGOTIATION SKILL ASSIGNED
```

---

# 16. Persona Is Not Tool Authority

```text
"DEVOPS PERSONA"
≠
PRODUCTION DEPLOYMENT TOOL ACCESS
```

---

# 17. Persona Is Not Model Approval

Persona may prefer response characteristics.

It may not authorize a Model/provider.

---

# 18. Persona Is Not Memory Authority

```text
"CUSTOMER SUCCESS PERSONA"
≠
ACCESS TO ALL CUSTOMER MEMORY
```

---

# 19. Persona Is Not Policy

Persona operates under Policy.

It does not define or override Policy.

---

# 20. Persona Is Not Prompt

Prompt may realize Persona instructions.

```text
PERSONA
≠
PROMPT TEXT
```

---

# 21. Persona Is Not Model Personality

Provider/model behavior is not automatically the Mianx Persona.
