# Mianx.ai Memory Engine Retrieval Engine

> **This document defines the target-state Retrieval Engine for the
> Mianx.ai Memory Engine.**
>
> **The Retrieval Engine discovers, filters, validates, ranks, assembles,
> and returns eligible Memory candidates for an authorized request.**
>
> **Retrieval is not authorization. Search relevance, Vector similarity,
> lexical match, graph connectivity, recency, popularity, Model ranking,
> or historical usage cannot override Project scope, Customer scope,
> Tenant scope, classification, Memory lifecycle, current identity,
> current role, current Verifiable Work Envelope, or governing policy.**
>
> **Trusted scope must come from authoritative control state. Free-form
> query text must never be treated as sufficient proof of Project,
> Customer, Tenant, User, Agent, or administrative authority.**
>
> **The Retrieval Engine may use Exact, Metadata, Lexical, Semantic,
> Temporal, Knowledge Graph, or Hybrid retrieval strategies, but every
> strategy must converge on the same hard governance boundaries before
> protected information can be disclosed or placed into runtime Context.**
>
> **A candidate can be relevant and still be ineligible. A result can be
> eligible and still be low-authority. A result can be authoritative and
> still be stale. A Memory item can be current and still be outside the
> requester's Work Envelope.**
>
> **This document does not define universal `top_k`, similarity
> thresholds, latency targets, result limits, ranking weights, cache TTLs,
> graph-depth limits, or retry counts. Those values must be established
> from implementation evidence, workload characteristics, risk, and
> approved operating policy.**
>
> **Retrieval Engine implementation, scope isolation, hard filtering,
> ranking, Vector retrieval, Graph retrieval, Context integration,
> monitoring, and Production readiness remain `NOT_PROVEN` unless
> separately demonstrated by controlled implementation Evidence.**

# 3. Retrieval Engine Mission

> **Return the most useful eligible Memory for the current authorized
> purpose while treating Security, scope, lifecycle, classification,
> authority, temporal validity, and Privacy as hard controls rather than
> ranking preferences.**
