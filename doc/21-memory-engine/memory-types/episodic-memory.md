# Mianx.ai Memory Engine Episodic Memory

> **This document defines Episodic Memory as a governed Memory Type within
> the Mianx.ai Memory Engine.**
>
> **Episodic Memory represents bounded historical experiences and events:
> what occurred, when it occurred, which Actors or systems participated,
> which entities were involved, under which Project, Customer, Tenant,
> workflow, session, or Task context it occurred, what was observed, what
> actions occurred, and what outcomes were recorded.**
>
> **An Episode is a recorded representation of an experience. It is not
> automatically proof that every statement inside the Episode is factually
> correct. Episodes may contain observations, user statements, model
> outputs, Tool responses, inferred interpretations, external content,
> failures, incomplete information, and disputed claims.**
>
> **Episodic Memory is historical by nature. Historical access,
> permissions, approvals, roles, outcomes, or actions contained in an
> Episode do not recreate current authority. Current identity, role,
> Verifiable Work Envelope, lifecycle, policy, Project, Customer, Tenant,
> Privacy, and Security controls remain authoritative at retrieval and
> action time.**
>
> **Temporal ordering must preserve uncertainty. Event time, observation
> time, record time, and ingestion time are distinct. Late-arriving events,
> asynchronous systems, clock skew, incomplete timestamps, and equal
> timestamps mean that exact real-world ordering may not always be known.**
>
> **Episodic Memory can provide historical Evidence for Continuous
> Learning, incident analysis, workflow improvement, retrieval, Context,
> and Knowledge Graph relationships. It must not silently transform
> correlation into causation, historical behavior into policy, or repeated
> experience into canonical enterprise knowledge.**
>
> **This document defines target-state Episodic Memory semantics only. It
> does not prove that an Episodic Memory store, Episode ingestion runtime,
> Episode identity service, temporal index, retrieval engine, lifecycle
> enforcement service, Customer/Tenant isolation layer, monitoring
> pipeline, or Production Episodic Memory capability currently exists.**

# 3. Episodic Memory Mission

The mission is:

> **Preserve governed historical experience with enough temporal,
> contextual, provenance, scope, and outcome information to support safe
> recall, investigation, learning, and decision support without converting
> history into current authority or unsupported truth.**

# 4. Episodic Memory Definition

Episodic Memory is Memory of:

```text
WHAT HAPPENED

WHEN IT HAPPENED

WHERE / IN WHICH SCOPE IT HAPPENED

WHO OR WHAT PARTICIPATED

WHAT WAS OBSERVED

WHAT ACTION OCCURRED

WHAT OUTCOME FOLLOWED

WHAT EVIDENCE SUPPORTS THE RECORD
```

# 6. Episode

An Episode is a governed bounded representation of one meaningful
experience or event sequence.

---

# 7. Event

An Event is a distinct occurrence represented within or by an Episode.

Examples may include:

```text
TASK STARTED

TOOL CALLED

TOOL RETURNED RESULT

AGENT MADE DECISION

CORRECTION RECEIVED
```

# 8. Episode vs Event

A simple Episode may represent one Event.

A complex Episode may contain a sequence of related Events.
