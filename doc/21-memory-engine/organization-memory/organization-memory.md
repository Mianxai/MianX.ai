# Mianx.ai Memory Engine Organization Memory

> **This document defines Organization Memory as a governed Memory domain
> within the Mianx.ai Memory Engine.**
>
> **Organization Memory is the institutional Memory of Mianx.ai: durable
> enterprise knowledge, approved operating knowledge, validated shared
> learning, organizational history, reusable patterns, governed decisions,
> shared terminology, architectural knowledge, and other information
> explicitly authorized for organization-level use.**
>
> **Organization Memory is not a global container into which all Project,
> Customer, Tenant, User, Agent, Conversation, or operational Memory is
> copied.**
>
> **Customer-specific Memory remains Customer-scoped by default. Project
> Memory remains Project-scoped by default. Tenant Memory remains
> Tenant-scoped by default. User Memory remains purpose- and
> Privacy-scoped. Agent Memory remains bounded by Agent authority.**
>
> **Knowledge may become Organization Memory only through a governed
> admission, generalization, validation, promotion, or canonicalization
> process appropriate to its risk and authority.**
>
> **Organization Memory does not automatically become canonical. Shared
> organizational knowledge may still be tentative, informational,
> historical, inferred, disputed, non-authoritative, or limited to a
> particular organizational purpose.**
>
> **Organization Memory cannot expand Agent authority. Knowledge that an
> Agent can retrieve does not grant permission to execute actions,
> access Tools, cross Customer boundaries, modify policies, or exercise
> Founder-reserved authority.**
>
> **This document defines target-state Organization Memory semantics only.
> Organization Memory storage, promotion pipelines, isolation controls,
> generalization runtime, retrieval, canonicalization, monitoring,
> enforcement, and Production capability remain `NOT_PROVEN` unless
> separate implementation Evidence establishes them.**
