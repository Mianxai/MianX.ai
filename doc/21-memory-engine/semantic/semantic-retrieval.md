# Mianx.ai Memory Engine Semantic Retrieval

> **This document defines the target-state Semantic Retrieval model for
> the Mianx.ai Memory Engine.**
>
> **Semantic Retrieval finds governed knowledge propositions, concepts,
> definitions, relationships, facts, inferred knowledge, and other
> Semantic Memory by meaning rather than relying only on literal text
> equality.**
>
> **Semantic Retrieval is not a truth engine. A high similarity score,
> strong embedding match, frequent statement, recent statement, Model
> confidence, graph connectivity, or high ranking position cannot by
> itself establish that a proposition is true, current, canonical,
> authoritative, applicable, or authorized for the requester.**
>
> **Semantic Memory retrieval must preserve source provenance, authority
> class, confidence where applicable, scope, classification, lifecycle,
> temporal validity, contradiction state, Version, and current
> authorization.**
>
> **Semantic Retrieval must preserve hard Project, Customer, Tenant, User,
> Agent, classification, lifecycle, and Verifiable Work Envelope
> boundaries before protected Memory may be disclosed or placed into
> runtime Context.**
>
> **Different propositions may be semantically similar while differing in
> scope, time, authority, Customer applicability, negation, exceptions, or
> factual status. Semantic systems must therefore avoid collapsing meaning
> solely from Vector proximity.**
>
> **This document defines no universal similarity threshold, `top_k`,
> reranking weight, embedding dimension, graph depth, lexical weight,
> authority weight, recency weight, cache TTL, or latency target. Such
> values require implementation-specific validation and controlled
> Production Evidence.**
>
> **Semantic Retrieval runtime, Vector search, proposition reconstruction,
> contradiction retrieval, temporal filtering, Project/Customer/Tenant
> isolation, Context integration, monitoring, Evidence, and Production
> capability remain `NOT_PROVEN` unless separately demonstrated.**
