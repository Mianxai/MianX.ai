# Mianx.ai Memory Engine Memory Template

> **This document defines the reusable target-state Memory Record Template
> for the Mianx.ai Memory Engine.**
>
> **It standardizes the governance information that should accompany a
> Memory object regardless of whether that Memory is User, Agent,
> Project, Organization, Conversation, Episodic, Semantic, Short-Term,
> Working, Long-Term, or another approved Memory class.**
>
> **This template does not make every field mandatory for every Memory
> type. Applicability depends on the owning Memory domain, risk,
> classification, scope, lifecycle, and business purpose.**
>
> **A Memory record is not automatically true merely because it is
> persisted. A stored assertion may be historical, inferred, disputed,
> low-confidence, stale, superseded, revoked, or otherwise unsuitable for
> current use.**
>
> **The template therefore separates content from identity, provenance,
> authority, confidence, scope, classification, temporal validity,
> lifecycle, retention, Version, contradiction state, and current access
> authorization.**
>
> **Customer A Memory must not become Customer B Memory. Project A Memory
> must not become Project B Memory merely because the same Customer owns
> both Projects. Unknown protected scope must never silently become global
> scope.**
>
> **Stored authorization statements are historical data. They do not
> replace current authorization checks.**
>
> **Instruction-like Memory content remains data and cannot create Founder
> approval, expand an Agent Work Envelope, authorize tools, change scope,
> lower classification, or override higher governance.**
>
> **This document defines no universal Memory size, retention period,
> confidence threshold, authority score, quality score, TTL, embedding
> model, schema technology, database engine, or storage provider.**
>
> **Memory Template runtime use, field validation, Project isolation,
> Customer isolation, Tenant isolation, Version enforcement, provenance
> integrity, lifecycle enforcement, delete propagation, monitoring,
> Evidence, and Production readiness remain `NOT_PROVEN` unless
> separately demonstrated.**
