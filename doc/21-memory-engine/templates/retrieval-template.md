# Mianx.ai Memory Engine Retrieval Template

> **This document defines the reusable target-state governed Retrieval
> Template for the Mianx.ai Memory Engine.**
>
> **The template standardizes retrieval requests, candidate discovery,
> hard eligibility checks, current authorization evaluation, ranking,
> result construction, provenance preservation, denial handling, and
> retrieval Evidence across lexical, structured, semantic, Vector, Graph,
> Episodic, and hybrid retrieval strategies.**
>
> **Retrieval candidate generation and authorization are separate stages.
> A Memory record may be an excellent lexical match, a near-perfect Vector
> match, strongly connected in the Knowledge Graph, historically relevant,
> frequently accessed, canonical in another scope, or previously
> authorized and still remain ineligible for the current request.**
>
> **Hard scope, authorization, classification, lifecycle, purpose, and
> temporal controls must not be converted into soft ranking preferences.**
>
> **Project A Memory must not reach Project B simply because both belong to
> the same Customer. Customer A Memory must not reach Customer B through
> semantic similarity, shared indexes, Graph traversal, cache reuse,
> fallback logic, or reranking.**
>
> **Stored authorization statements and historical access decisions are
> evidence of past state. They do not grant current access.**
>
> **Retrieval output provides information. It does not create Agent action
> authority, Founder approval, tool permission, scope expansion, policy
> exceptions, or Work Envelope expansion.**
>
> **The template is provider- and algorithm-neutral. It defines no
> universal `top_k`, score threshold, Vector distance, reranking formula,
> lexical weight, Graph depth, query timeout, token count, freshness
> window, or latency objective.**
>
> **Retrieval runtime behavior, authorization enforcement, Project
> isolation, Customer isolation, Tenant isolation, stale-derivative
> protection, ranking quality, denial safety, observability, Evidence, and
> Production readiness remain `NOT_PROVEN` unless separately
> demonstrated.**

# 5. Retrieval Definition

Retrieval is:

> **The governed process of discovering Memory candidates and returning
> only the subset eligible for the current principal, purpose, scope,
> lifecycle, classification, temporal context, and authorization state.**
