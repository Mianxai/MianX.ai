# 6. Documentation Status Vocabulary

The AI OS documentation domain uses the following content states.

## 6.1 EMPTY_PLACEHOLDER

The file exists but contains no substantive governed content.

```text
EMPTY_PLACEHOLDER
```

does not mean:

```text
MISSING_FILE
```

---

## 6.2 CONTENT_COMPLETE_FOR_REVIEW

The document contains substantive content sufficient for structured review.

It does not mean approved or canonical.

---

## 6.3 EXISTING_SUBSTANTIVE_REVIEW_PENDING

The document already contained substantive content before the current AI OS
completion cycle.

It must be preserved and reconciled rather than blindly overwritten.

---

## 6.4 APPROVED

The exact document version has completed its required approval process.

No document in this domain is currently proven Approved under the current
review cycle.

---

## 6.5 CANONICAL

A document becomes canonical only after explicit governance promotion.

# 8. Document ID Registry Principle

Document IDs must be:

- unique;
- stable;
- machine-readable;
- traceable;
- version-independent where practical.

This Index assigns IDs to documents being created during the current
completion cycle.

For substantive pre-existing documents, their internal source ID must be
preserved if one already exists.

Therefore:

```text
INDEX PROPOSED ID
≠
PERMISSION TO OVERWRITE EXISTING INTERNAL ID
```

If a conflict is discovered during reconciliation:

1. preserve the existing source;
2. record the conflict;
3. determine the authoritative ID;
4. update cross-references;
5. do not silently create duplicate authority.
