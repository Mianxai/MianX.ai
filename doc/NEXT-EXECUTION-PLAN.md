# 5. Why the Earlier Plan Was Superseded

The earlier plan was useful because it promoted:

- evidence before completion;
- repository verification;
- build and test verification;
- secure deployment;
- Documentation reconciliation;
- backup and recovery review;
- safe AI behavior;
- Founder review.

However, it became unsuitable as the active execution authority because it
contained assumptions that no longer matched the verified state.

These included:

- a fixed 30-day planning horizon;
- old `Phase 0` through `Phase 5` execution terminology;
- old PR #1 references;
- repository access work already overtaken by later evidence;
- a migration still shown as future work;
- a five-file canonical hierarchy;
- a broad MianX Core gap audit;
- a Core-first next sprint;
- RestaurantOS and PoultryOS being blocked only by broad Core completion;
- duplicated authority with the newer Execution Board;
- statuses that remained `Not Started` after later work occurred.

The file is therefore retained for history but removed from active control.
