# Folder Responsibility Matrix — Folders 01–10

## 1. Document Purpose

This document defines the proposed architectural responsibilities, ownership boundaries, governance responsibilities, permitted content, prohibited content, dependencies, and consumers for top-level folders `01-governance` through `10-devops`.

This document is a governed draft.

It does not authorize:

- Folder deletion
- Folder renaming
- Folder movement
- Document movement
- Document merging
- Canonical promotion
- Content replacement

Responsibility assignments in this document SHALL remain provisional until folder content audits, boundary validation, overlap analysis, ownership verification, and governance review are complete.

---

## 2. Scope

This module covers exactly the following folders:

```text
01-governance
02-company
03-product
04-system
05-workforce
06-engineering
07-platform
08-data
09-security
10-devops
```

Each folder SHALL appear in only one Folder Responsibility Matrix module.

---

## 3. Interpretation Rules

### Rule 001 — Draft Authority

The assignments in this document represent proposed target responsibilities.

They SHALL NOT be treated as final canonical assignments while this document has:

```yaml
status: Draft
canonical: false
```

---

### Rule 002 — Existing Content Protection

Existing folder content SHALL remain protected during responsibility analysis.

A responsibility conflict does not automatically mean that a document must be deleted or moved.

Every conflict SHALL first receive:

- Content review
- Canonical-source decision
- Dependency analysis
- Migration recommendation
- Governance approval

---

### Rule 003 — One Primary Responsibility

Every top-level folder SHALL own one primary architectural responsibility.

Supporting responsibilities MAY exist only when they directly serve the primary responsibility.

---

### Rule 004 — Layer Separation

The repository distinguishes between:

- Constitutional knowledge
- Company knowledge
- Product knowledge
- System design
- Human workforce
- Engineering practices
- Platform foundations
- Data governance
- Security governance
- DevOps delivery practices

These responsibilities SHALL remain distinguishable even when they collaborate.

---

### Rule 005 — Specialized Platform Boundaries

Folders `01–10` MAY define foundational knowledge that is implemented by later specialized folders.

Examples:

```text
09-security
    defines security governance, requirements and controls

41-security-platform
    implements reusable security platform capabilities
```

```text
08-data
    defines data architecture, governance and models

42-data-platform
    implements reusable data platform services
```

```text
10-devops
    defines DevOps practices, automation and delivery pipelines

39-deployment
    defines deployment execution and environment delivery
```
