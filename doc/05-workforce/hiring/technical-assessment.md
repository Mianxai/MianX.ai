# Technical Assessment

> This document defines the technical assessment framework used by MIANX to evaluate candidates for engineering and technical roles. The objective is to measure practical ability, engineering thinking, and problem-solving skills using realistic scenarios rather than theoretical examinations.

Technical assessments should reflect the actual work candidates will perform after joining MIANX.

---

# Purpose

The purpose of the Technical Assessment process is to objectively evaluate a candidate's technical competency, engineering mindset, and ability to solve real-world problems.

---

# Objectives

The assessment process aims to:

- Evaluate technical knowledge
- Measure practical engineering skills
- Assess problem-solving ability
- Verify architectural thinking
- Evaluate code quality
- Measure debugging capability
- Assess communication during technical discussions
- Reduce hiring bias
- Standardize technical evaluations
- Improve hiring quality

---

# Assessment Principles

Every technical assessment should be:

- Practical
- Fair
- Role-specific
- Consistent
- Objective
- Time appropriate
- Well documented
- Relevant to actual job responsibilities

The assessment should evaluate engineering ability—not memorization.

---

# Assessment Workflow

```text
Candidate Screening

↓

Interview Invitation

↓

Technical Assessment

↓

Submission Review

↓

Technical Interview

↓

Panel Evaluation

↓

Hiring Recommendation
```

Each stage should have clear evaluation criteria.

---

# Assessment Types

Depending on the position, one or more assessment types may be used.

## Coding Challenge

Candidates solve programming problems that resemble real production work.

Example activities:

- REST API development
- Backend service implementation
- Data processing
- Bug fixing
- Unit testing
- Algorithm implementation

---

## System Design

Used primarily for senior positions.

Candidates may be asked to design:

- Distributed systems
- AI platforms
- Cloud architecture
- Microservices
- Databases
- Event-driven systems
- High-availability infrastructure

Evaluation focuses on design decisions rather than a single "correct" answer.

---

## Debugging Exercise

Candidates receive an intentionally broken project and identify:

- Bugs
- Performance issues
- Security problems
- Logic errors
- Deployment issues

This evaluates troubleshooting skills.

---

## Code Review Exercise

Candidates review an existing codebase and provide feedback regarding:

- Code quality
- Maintainability
- Security
- Performance
- Readability
- Best practices

This reflects everyday engineering responsibilities.

---

## Pair Programming

Candidates collaborate with an interviewer to solve a problem together.

Evaluation areas include:

- Communication
- Collaboration
- Problem-solving
- Adaptability
- Coding practices

Pair programming evaluates how candidates work with teammates.

---

## Portfolio Review

Candidates may present:

- Previous projects
- Open-source contributions
- Research work
- AI models
- Infrastructure projects
- Personal applications

Interviewers should focus on understanding the candidate's actual contributions.

# Assessment by Role

| Role | Recommended Assessment |
|------|------------------------|
| Frontend Engineer | UI implementation, accessibility, performance |
| Backend Engineer | APIs, databases, scalability |
| Full Stack Engineer | End-to-end application development |
| DevOps Engineer | Infrastructure automation, CI/CD |
| Platform Engineer | Cloud architecture, reliability |
| AI Engineer | ML models, data pipelines, prompt engineering |
| Security Engineer | Security review, threat analysis |
| QA Engineer | Test automation, quality strategy |

Assessment content should match the responsibilities of the role.

---

# Evaluation Criteria

Candidates should be evaluated across:

| Category | Description |
|----------|-------------|
| Technical Accuracy | Correctness of solution |
| Problem Solving | Approach and reasoning |
| Code Quality | Maintainability and readability |
| Architecture | Design decisions |
| Performance | Efficiency and optimization |
| Security | Secure coding practices |
| Testing | Validation and test coverage |
| Documentation | Clarity of explanations |
| Communication | Technical discussion |
| Learning Ability | Adaptability and curiosity |

---

# Technical Scorecard

Suggested weighting:

| Category | Weight |
|----------|-------:|
| Problem Solving | 25% |
| Technical Knowledge | 20% |
| Code Quality | 15% |
| Architecture | 15% |
| Security | 10% |
| Testing | 5% |
| Documentation | 5% |
| Communication | 5% |

Departments may adjust weights depending on the role.

---

# Assessment Guidelines

Interviewers should:

- Explain objectives clearly
- Provide necessary context
- Answer clarification questions
- Avoid giving solutions
- Observe reasoning process
- Evaluate consistently
- Document findings

Candidates should understand what is expected before beginning.

---

# Candidate Expectations

Candidates should:

- Complete work independently unless collaboration is expected
- Explain technical decisions
- Write maintainable code
- Ask clarifying questions when necessary
- Submit work within the allotted time
- Follow provided instructions

Honest problem-solving is valued over perfect answers.

---

# Review Process

After submission:

```text
Assessment Review

↓

Individual Evaluations

↓

Technical Discussion

↓

Scorecard Completion

↓

Panel Recommendation

↓

Hiring Decision
```

Multiple reviewers improve consistency and reduce bias.

---

# Documentation Requirements

Maintain records for:

- Assessment instructions
- Candidate submissions
- Reviewer comments
- Evaluation scorecards
- Technical feedback
- Final recommendation

Assessment materials should be stored securely.

---

# Confidentiality

Assessment content should:

- Be shared only with authorized personnel
- Remain confidential
- Not be redistributed externally
- Be updated periodically to prevent reuse
- Protect candidate intellectual property

---

# Assessment Metrics

Recommended metrics:

| Metric | Description |
|--------|-------------|
| Assessment Completion Rate | Completed assessments |
| Average Assessment Score | Overall candidate performance |
| Technical Pass Rate | Candidates advancing |
| Assessment Duration | Average completion time |
| Reviewer Consistency | Evaluation alignment |
| Hiring Success Rate | Long-term performance after hiring |
| Candidate Feedback Score | Assessment experience |

Metrics should be reviewed regularly to improve assessment quality.

---

# Best Practices

Recommended:

- Use real-world engineering scenarios
- Keep assessments role-specific
- Evaluate thinking, not memorization
- Review submissions consistently
- Provide clear instructions
- Limit unnecessary time pressure
- Update assessments regularly
- Document evaluation outcomes

---

# Anti-Patterns

Avoid:

- Brain teaser questions unrelated to the role
- Excessively long take-home assignments
- Judging candidates solely on speed
- Using outdated technologies
- Reusing publicly available assessment answers
- Ignoring communication skills
- Unstructured evaluations
- Making hiring decisions based on a single exercise
