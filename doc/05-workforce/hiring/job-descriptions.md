# Job Descriptions

> This document defines the standards for creating, maintaining, approving, and publishing job descriptions within MIANX. Every job description should clearly communicate the purpose of the role, responsibilities, required qualifications, expectations, and growth opportunities.

A well-written job description helps attract the right candidates while ensuring consistency across the hiring process.

---

# Purpose

The purpose of this document is to standardize how job descriptions are written and managed throughout the organization.

---

# Objectives

The job description process aims to:

- Clearly define every role
- Improve candidate quality
- Standardize hiring
- Reduce ambiguity
- Support workforce planning
- Improve interview consistency
- Set performance expectations
- Strengthen employer branding
- Improve internal mobility
- Maintain documentation quality

---

# Guiding Principles

Every job description should be:

- Clear
- Accurate
- Inclusive
- Realistic
- Role-specific
- Up-to-date
- Easy to understand
- Business aligned

Job descriptions should describe actual responsibilities rather than idealized expectations.

---

# Job Description Lifecycle

```text
Workforce Planning

↓

Position Request

↓

Role Definition

↓

Job Description Draft

↓

Department Review

↓

HR Review

↓

Approval

↓

Publication

↓

Periodic Review

↓

Archive / Update
```

Each job description should have an owner responsible for maintaining it.

---

# Standard Structure

Every job description should contain:

1. Job Title
2. Department
3. Reporting Manager
4. Employment Type
5. Location
6. Role Summary
7. Key Responsibilities
8. Required Skills
9. Preferred Qualifications
10. Experience Requirements
11. Tools & Technologies
12. Success Metrics
13. Career Growth
14. Benefits
15. Hiring Process

---

# Job Metadata

Each position should define:

| Field | Description |
|---------|-------------|
| Job ID | Internal identifier |
| Job Title | Official position title |
| Department | Owning department |
| Team | Functional team |
| Employment Type | Full-Time, Part-Time, Contract, Internship |
| Work Model | Remote, Hybrid, Onsite |
| Level | Junior, Mid, Senior, Lead, Principal |
| Reports To | Direct manager |
| Location | Office or region |
| Status | Draft, Approved, Published, Closed |

---

# Role Summary

The summary should explain:

- Why the role exists
- Primary business purpose
- Team mission
- Overall impact

The summary should typically be 3–5 concise paragraphs.

---

# Responsibilities

Responsibilities should:

- Use action-oriented language
- Describe measurable outcomes
- Reflect actual work
- Be prioritized
- Avoid unnecessary detail

Example:

- Design scalable backend systems
- Develop production-ready software
- Review pull requests
- Mentor junior engineers
- Collaborate with product teams
- Improve platform reliability

---

# Required Qualifications

Required qualifications should include only essential requirements.

Examples:

- Core technical skills
- Required programming languages
- Professional experience
- Communication skills
- Legal work authorization (where applicable)

Avoid unrealistic requirements that unnecessarily limit qualified candidates.

---

# Preferred Qualifications

Preferred qualifications may include:

- Advanced certifications
- Open-source contributions
- Leadership experience
- Cloud certifications
- Research publications
- Industry expertise

Preferred qualifications should not be treated as mandatory.

---

# Technical Skills

When applicable, specify:

- Programming Languages
- Frameworks
- Databases
- Cloud Platforms
- DevOps Tools
- AI Frameworks
- Testing Tools
- Security Knowledge

Skills should align directly with the responsibilities of the role.

---

# Experience Levels

Recommended guidelines:

| Level | Experience |
|--------|-----------:|
| Intern | Student / Entry Level |
| Junior | 0–2 Years |
| Mid-Level | 2–5 Years |
| Senior | 5–8 Years |
| Lead | 8–12 Years |
| Principal | 12+ Years |

Experience requirements should remain flexible when candidates demonstrate exceptional capability.

---

# Success Metrics

Every role should define measurable success indicators.

Examples:

- Delivery quality
- Feature completion
- Customer satisfaction
- System reliability
- Code quality
- Documentation quality
- Team collaboration
- Process improvement

Success metrics should align with performance evaluations.

---

# Career Growth

Job descriptions should communicate possible career paths.

Example:

```text
Intern

↓

Junior Engineer

↓

Software Engineer

↓

Senior Engineer

↓

Staff Engineer

↓

Principal Engineer

↓

Engineering Manager
```

Career progression should remain transparent.

---

# Compensation Information

When appropriate, include:

- Salary range
- Benefits
- Equity eligibility
- Bonus structure
- Learning budget
- Equipment provided
- Leave policies

Compensation should comply with company policies and applicable regulations.

---

# Review Process

Every job description should be reviewed by:

- Hiring Manager
- Department Head
- HR
- Executive Leadership (if required)

Approval is required before publication.

---

# Maintenance

Job descriptions should be reviewed:

| Event | Action |
|--------|--------|
| New Position | Create |
| Organizational Change | Update |
| Annual Review | Verify |
| Role Expansion | Revise |
| Hiring Campaign | Review |
| Position Closure | Archive |

Outdated job descriptions should not be used for active recruitment.

---

# Documentation Standards

Each job description should:

- Follow a consistent template
- Use clear language
- Avoid discriminatory wording
- Include version history
- Identify the document owner
- Be stored in the central documentation repository

---

# Best Practices

Recommended:

- Focus on outcomes instead of tasks
- Keep requirements realistic
- Highlight growth opportunities
- Explain team purpose
- Review descriptions regularly
- Use inclusive language
- Align descriptions with actual work
- Keep formatting consistent

---

# Anti-Patterns

Avoid:

- Unrealistic experience requirements
- Excessive qualification lists
- Vague responsibilities
- Generic descriptions
- Outdated technology requirements
- Copying descriptions from unrelated roles
- Undefined reporting structures
- Missing success criteria

---

# Future Evolution

The job description framework will evolve through:

- AI-assisted job description generation
- Skills-based role definitions
- Competency mapping
- Internal career frameworks
- Automated document reviews
- Organization-wide role taxonomy
- Global hiring standards
- Workforce intelligence integration
