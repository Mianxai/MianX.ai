# Security Architect

> This document defines the responsibilities, authority, expectations, and performance standards of the Security Architect at MIANX.

The Security Architect is responsible for designing, governing, and continuously improving the organization's security architecture across applications, infrastructure, cloud platforms, networks, identities, data, and engineering systems.

Unlike Security Engineers who implement security controls, the Security Architect defines the long-term security strategy, enterprise security standards, architecture patterns, governance, and technical direction for the organization.

---

# Purpose

The purpose of the Security Architect role is to establish secure-by-design engineering practices that protect organizational assets, customer data, business operations, and technology platforms.

---

# Mission

The Security Architect exists to:

- Design secure systems
- Reduce organizational risk
- Establish security standards
- Protect enterprise assets
- Enable secure software delivery
- Improve security maturity
- Support compliance initiatives
- Drive security innovation

# Enterprise Security Responsibilities

- Zero Trust Architecture
- Defense-in-Depth Strategy

- Cloud Network Security

- Cloud Compliance

Cloud platforms should remain secure throughout their lifecycle.

# Security Governance Responsibilities

The Security Architect establishes:

- Security Policies
- Security Standards
- Security Baselines
- Risk Management Frameworks
- Security Audits
- Security Metrics
- Governance Processes
- Security Reviews

---

# Threat Modeling Responsibilities

The Security Architect leads:

- Threat Modeling
- Risk Assessments
- Attack Surface Analysis
- Security Design Reviews
- Vulnerability Prioritization
- Security Architecture Reviews
- Control Validation
- Risk Mitigation Planning

Threat modeling should be performed for all critical systems.

# Compliance Responsibilities

The Security Architect supports compliance initiatives including:

- ISO 27001
- SOC 2
- GDPR
- PCI DSS
- HIPAA *(where applicable)*
- Internal Security Policies
- Customer Security Requirements
- Regulatory Compliance

Compliance should complement—not replace—good security engineering.

---

# Decision Authority

The Security Architect has authority over:

- Security architecture
- Security standards
- Security design reviews
- Security governance
- Enterprise security controls
- Identity architecture
- Cryptographic standards
- Security tooling standards
- Technical security policies
- Risk mitigation strategies

Enterprise technology strategy remains under the CTO, while enterprise security governance remains under the CISO.

- Driving security improvements

Leadership is demonstrated through proactive risk reduction and engineering enablement.
