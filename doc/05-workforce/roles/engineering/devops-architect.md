# DevOps Architect

> This document defines the responsibilities, authority, expectations, and performance standards of the DevOps Architect at MIANX.

The DevOps Architect is responsible for designing, governing, and continuously improving the organization's DevOps architecture, cloud infrastructure, automation platforms, CI/CD ecosystem, observability solutions, and deployment strategies.

Unlike a DevOps Technical Lead, the DevOps Architect focuses on long-term platform architecture, engineering standards, automation strategy, infrastructure scalability, and operational excellence across the organization.

---

# Purpose

The purpose of the DevOps Architect role is to establish a secure, scalable, automated, and resilient infrastructure platform that enables engineering teams to deliver software rapidly, reliably, and safely.

---

# Mission

The DevOps Architect exists to:

- Design scalable infrastructure
- Standardize DevOps practices
- Automate engineering workflows
- Improve deployment reliability
- Enhance platform security
- Increase engineering productivity
- Build resilient systems
- Support organizational growth

---

The DevOps Architect provides technical leadership across all DevOps and platform engineering initiatives.

# Infrastructure Responsibilities

- Virtual Infrastructure
- Cloud Networks
- Storage Platforms

# Cloud Responsibilities

The DevOps Architect establishes standards for:

- Microsoft Azure
- Google Cloud Platform
- Hybrid Cloud
- Multi-cloud Deployments
- Cloud Networking
- Identity Management
- Cloud Cost Optimization

# CI/CD Responsibilities

The DevOps Architect designs and governs:

- Continuous Integration
- Continuous Delivery
- Continuous Deployment
- Release Pipelines
- GitOps Workflows
- Deployment Automation
- Artifact Management
- Rollback Strategies

Deployment pipelines should minimize manual intervention while maximizing deployment safety.

# Infrastructure as Code Responsibilities

The DevOps Architect defines standards for:

- Terraform
- OpenTofu
- Ansible
- Helm
- Kubernetes Manifests
- CloudFormation *(where applicable)*
- Pulumi *(where applicable)*
- Infrastructure Versioning

Infrastructure must be fully automated, reproducible, and version controlled.

Platforms should simplify software delivery for engineering teams.
