# Mianx.ai Brand System

**Midnight Intelligence + Titanium Precision**

This is the single canonical design language for Mianx.ai. Every surface —
website, admin dashboard, Founder Workspace, product UI, decks, and anything
generated by Stitch, v0, Figma, or Cursor — follows it. The Founder-approved
final HTML in `design/approved/final-website/` remains the approved *layout*
reference; this document defines the *system* those layouts express.

The machine-readable source of truth for the values below is the `--mx-*`
custom-property block at the top of `app/globals.css`. When the two disagree,
this document is the intent and `globals.css` is the bug.

---

## 1. Brand idea

Mianx.ai is an AI-native Business Operating System — an engineered platform a
governed AI workforce runs on. The brand has to read as *infrastructure you
would trust with your company*, not as a consumer AI toy or an agency.

The MX mark carries four ideas, in this order:

| Idea | Expressed as |
|---|---|
| Sapphire intelligence and technology | Sapphire blue as the single primary hue |
| Titanium precision and reliability | Cool machined greys, hairline borders, exact alignment |
| Enterprise-scale power | Deep midnight ground, generous space, restraint |
| A controlled, trustworthy future | Cyan used sparingly as a signal, never as decoration |

**Deliberately not:** playful, neon, "AI startup gradient soup", crypto,
gaming, or maximalist. Confidence here comes from control, not intensity.

## 2. Brand personality

- **Engineered, not decorated.** Every visual element earns its place.
- **Calm under load.** The interface never shouts; severity is reserved for
  states that are genuinely severe.
- **Precise.** Alignment, spacing, and type sizes come from the scale, not
  from taste applied per screen.
- **Honest.** No fabricated metrics, logos, testimonials, or status badges.
  This is a brand rule, not only an editorial one — see §12.
- **Quietly premium.** Depth via surface elevation and hairline borders, not
  via glow and blur.

## 3. Colour roles and exact tokens

```css
--mx-background: #050914;  /* Midnight navy — the ground plane, page background */
--mx-surface:    #0A1222;  /* One step up — nav bars, sidebars, sticky chrome  */
--mx-card:       #101A2D;  /* Two steps up — cards, panels, modals            */
--mx-primary:    #1677FF;  /* Sapphire — the brand hue; primary actions       */
--mx-bright:     #319CFF;  /* Bright sapphire — links, active/hover, accents  */
--mx-cyan:       #38C7FF;  /* Cyan — signal only: highlights, focus, data tips */
--mx-titanium:   #C9D2DF;  /* Titanium — secondary text, icons, hairline detail */
--mx-text:       #F5F8FC;  /* Ice white — primary text                        */
--mx-text-muted: #94A3B8;  /* Muted titanium — secondary/supporting text      */
--mx-border:     #22324A;  /* Structural hairline borders and dividers        */
```

**Role rules**

- Exactly one primary hue: sapphire. Cyan is an *accent*, never a second brand
  colour, and never covers large areas.
- Elevation reads through the background → surface → card ladder, not through
  shadow intensity.
- Titanium is the neutral. Pure `#FFFFFF` is reserved for text or icons on a
  filled sapphire control; never for large fills.
- Semantic colours (success/warning/danger) are functional, outside the brand
  palette, and only used for real state.

**Purple**

Purple is not a Mianx brand colour and must never be dominant. It is permitted
only as an almost imperceptible transitional glow between sapphire and cyan,
under ~10% opacity, in a decorative layer. Any purple that is legible as
"purple" is a bug. The legacy indigo/violet values still present in
`app/globals.css` under the `--primary` / `--accent` aliases are inherited from
the approved HTML and are scheduled for migration; nothing new may use them.

## 4. Gradient usage

Two gradients, with a hard rule about which goes behind text.

```css
/* Primary (bright) — gradient text, accent rules, decorative fills on midnight */
--mx-gradient-primary: linear-gradient(135deg, #126BFF 0%, #229DFF 55%, #38C7FF 100%);

/* Action (deep) — filled controls that carry white text or icons */
--mx-gradient-action:  linear-gradient(135deg, #0B4FCC 0%, #1163F0 55%, #126BFF 100%);
```

```css
/* Atmospheric background — hero and other full-bleed brand moments */
--mx-atmosphere:
  radial-gradient(circle at 20% 25%, rgba(22, 119, 255, .18), transparent 38%),
  radial-gradient(circle at 80% 75%, rgba(56, 199, 255, .10), transparent 34%),
  #050914;
```

Rules:

- **Never put white text on the primary gradient.** Its bright stops reach only
  ~2.9:1 against white. White text goes on the action gradient (≥4.5:1 at every
  stop). This is the reason two gradients exist.
- Gradient *text* (`background-clip: text`) uses the primary gradient, and only
  at ≥24px or bold ≥18.66px, where 3:1 applies. Never for body copy, labels,
  form text, or anything a user must read to complete a task.
- One gradient element per viewport as a focal point. Gradients on every card
  is the "AI startup" look this brand rejects.
- Fixed 135° angle. Do not animate gradient position as decoration.

## 5. Typography principles

The system is defined by *roles and scale*, not by a specific typeface, so the
company is never locked to a fashionable font. Today the roles resolve to
Inter (UI/body) and Space Grotesk (display) via `next/font`; swapping either is
a one-line change in `app/layout.jsx`.

| Role | Requirement |
|---|---|
| Display | Geometric or neo-grotesque sans, tight tracking, weights 600–700. Headings and stat numbers only. |
| UI / body | Highly legible neutral sans with true tabular figures and a wide weight range (300–700). |
| Mono | Only for code, IDs, keys, and log output. Never for emphasis. |

Principles:

- Self-hosted or framework-optimised fonts. No runtime CDN font requests.
- Two families maximum, plus mono. A third family is a redesign, not a tweak.
- Fluid display sizes via `clamp()`; body text stays at a fixed 16px base and
  is never below 14px.
- Line height ~1.1 for display, ~1.6–1.7 for body.
- Sentence case for headings and buttons. `UPPERCASE` only for small tags and
  eyebrows, with letter-spacing.
- Weight and size carry hierarchy. Colour does not — a heading must still read
  as a heading in monochrome.

## 6. Spacing and layout principles

- **4px base unit**, with an 8px working rhythm. Every gap, pad, and offset is
  a multiple. No arbitrary `13px`.
- Section rhythm: `6rem` vertical padding desktop, `4rem` mobile.
- Content max-width `1200px`; prose max-width `~65ch`; hero copy `~900px`.
- Gutters: `2rem` desktop, `1.5rem` mobile.
- Grids use `repeat(auto-fit, minmax(...))` so cards reflow rather than shrink
  below their legible width.
- Breakpoints: `1024px` and `768px`. Add a third only with a real reason.
- Whitespace is structural. When a screen feels crowded, remove content before
  reducing space.

## 7. Card, border and surface principles

- Surfaces step up the ladder: `--mx-background` → `--mx-surface` →
  `--mx-card`. Never skip a step to fake depth.
- **1px `--mx-border` hairlines** define structure. Borders, not shadows, are
  the primary way an edge is communicated — that is the "titanium precision"
  half of the system.
- Radii: `10–12px` controls, `16px` icon tiles, `20–24px` cards and panels.
  Consistent within a family.
- Shadows are for real elevation only (modals, dropdowns, hover lift): large,
  soft, near-black, low opacity. Shadows are never coloured for decoration.
- Card accents (a 3px top rule in the primary gradient, revealed on hover) are
  the sanctioned way to make a card feel alive.
- Hover: ≤8px lift, border brightening, one shadow step. No scaling of text
  containers, no rotation of content.

## 8. Motion philosophy

Motion exists to explain a state change. It is never the point.

- Durations `150–400ms`; page-level reveals up to `700ms`. Nothing loops
  purely for decoration.
- Easing: `cubic-bezier(0.2, 0.7, 0.2, 1)` for entrances, `ease` for hovers.
- Animate `opacity` and `transform` only. Never animate layout properties.
- One motion event per interaction. Two elements animating for the same cause
  is one too many.
- Scroll reveals are a single short fade-and-rise, triggered once, never
  reversed on scroll-up.
- `prefers-reduced-motion: reduce` is honoured in CSS *and* in JavaScript
  (including the 3D scene, which drops to a single static frame). Reduced
  motion must never mean reduced content.

## 9. 3D / WebGL progressive-enhancement rules

Binding for every 3D or canvas visual in any Mianx product. The live homepage
crashed on WebGL-less devices once; these rules exist so it cannot recur.

1. **The 3D layer is never required to render the page.** A static composition
   is server-rendered first and the canvas mounts on top of it.
2. **Detect the context the library actually requests.** three.js requests
   `webgl2` only (no WebGL1 fallback since r163) — probing WebGL1 green-lights
   devices that cannot run the scene.
3. **Release probe contexts** via `WEBGL_lose_context`; browsers cap live
   contexts (~16) and a leaked probe can starve the real canvas.
4. **Wrap construction in try/catch, and never leave an async path
   unhandled.** An un-awaited async effect body is how a renderer failure
   becomes a full-page crash.
5. **Add a scoped error boundary** around the scene subtree only. Never widen
   it into a global crash-suppressor.
6. **Handle `webglcontextlost`** by returning to the static composition, not by
   leaving a frozen frame.
7. **Full teardown on unmount**: cancel animation frames; remove every
   listener; disconnect every observer; dispose geometries, materials and the
   renderer; force context loss; remove the canvas.
8. **Survive Strict Mode.** Effects run twice in development: create a fresh
   canvas per run, share one module import, and never end up with two
   renderers.
9. **Budget by device.** Reduce geometry, particle count, pixel ratio and
   antialiasing on constrained devices (coarse pointer, narrow viewport, low
   `deviceMemory`/`hardwareConcurrency`, `saveData`). Skip pointer parallax
   without a hovering pointer.
10. **Pause when unseen.** Gate the loop on document visibility and on the
    canvas intersecting the viewport.
11. **Reduced motion means one static frame**, not a slower animation.
12. **Log the downgrade, don't hide it.** A single `console.warn` naming the
    reason. Silencing a console error without handling the failure is
    prohibited.
13. **Keep it decorative in the accessibility tree**: `aria-hidden="true"`, no
    focusable content, no information conveyed only in 3D.

Reference implementation: `components/public/HeroScene.jsx`,
`components/public/SceneBoundary.jsx`, `components/public/webgl.js`.

## 10. Accessibility requirements

- **WCAG 2.1 AA is the floor.** 4.5:1 for normal text, 3:1 for large text
  (≥24px, or ≥18.66px bold), 3:1 for UI component and focus indicators.
- Verified pairings on `--mx-background`: `--mx-text` ≈ 19:1;
  `--mx-text-muted` ≈ 7.8:1; `--mx-bright` ≈ 6.8:1.
- White on `--mx-gradient-action` ≥ 4.5:1 at every stop. White on
  `--mx-gradient-primary` fails and is prohibited behind text (§4).
- Focus is always visible: `2px` outline in `--mx-cyan` with `2px` offset.
  Never `outline: none` without an equivalent replacement.
- Colour is never the only carrier of meaning — pair it with text or an icon.
- Semantic HTML and landmarks: one `<h1>` per page, ordered headings, a skip
  link, and `<main>`.
- Every interactive element is keyboard reachable and operable; dialogs and
  menus trap focus, close on `Escape`, and restore focus to their trigger.
- Decorative visuals get `aria-hidden="true"`.
- Targets ≥44×44px on touch.
- The page must remain usable with JavaScript disabled and with WebGL absent.

## 11. Logo system recommendation

The responsive logo family below is a **specification, not a delivered asset**.
No new logo artwork is created in this phase. Every variant must be built from
one geometry so the family reads as a single mark.

| # | Variant | Purpose | Requirements |
|---|---|---|---|
| 1 | **Signature metallic 3D MX** | Hero moments, launch/press, brand films, wallpapers | Sapphire-to-cyan metal on midnight, titanium chamfered edges, one controlled specular highlight. Never used inline in UI, never below 96px. |
| 2 | **Flat responsive vector MX** | App/site chrome, favicons, avatars, partner walls | Single-path SVG, no gradient mesh, no shadow. Must stay legible at 16px; simplify interior detail below 32px rather than scaling it down. |
| 3 | **Wordmark combination** | Primary lockup: mark + "Mianx.ai" | Fixed clear space of one mark-width on all sides; fixed optical spacing between mark and wordmark. Horizontal by default, stacked variant for narrow/square slots. |
| 4 | **Monochrome** | Print, engraving, embroidery, single-colour partner use, dark-on-light documents | One-colour positive and knockout. Must survive with no gradient, no fill nuance, at 1-bit. |
| 5 | **Favicon / app icon** | Browser tab, PWA, mobile home screen, notifications | 16/32/48px favicon plus maskable 192/512px app icon. Solid sapphire ground, safe-area respected, no wordmark. |

Rules for all variants: never re-colour outside the palette, never add effects
(bevel, outer glow, drop shadow) to the flat mark, never stretch or rotate,
never place the mark on a busy photo without a solid or scrimmed backing, and
never recreate the mark with a live font.

## 12. Prohibited visual patterns

- Purple as a dominant or recognisable brand colour (§3).
- White or light text on the bright primary gradient (§4).
- Heavy glassmorphism: stacked blurs, frosted panels on frosted panels.
- Glow as decoration — neon outlines, glowing text, glowing borders on
  non-interactive elements.
- Chrome/metallic *text* effects. Metal is for variant 1 of the logo only.
- Decorative looping animation: floating particles over content, pulsing
  cards, spinning icons, marquees, animated gradient backgrounds.
- More than one focal gradient per viewport.
- Rainbow or multi-hue palettes; a second brand hue competing with sapphire.
- Drop shadows used to fake elevation on flat, non-elevated elements.
- Coloured shadows for decoration.
- Pure-black `#000000` grounds or pure-white `#FFFFFF` fills.
- Stock "AI" imagery: glowing brains, humanoid robots, neural-net wallpaper.
- Fabricated proof: invented logos, testimonials, metrics, or status badges.
- Text over imagery without a scrim, or below 4.5:1.
- Any 3D/WebGL visual that the page's rendering depends on (§9).
- Emoji as UI iconography in product surfaces.

## 13. Guidance for Stitch, v0 and Cursor

All three tools must produce output in this one design language. Give them the
system, not adjectives.

**Shared prompt preamble** (paste verbatim):

> Design system: "Midnight Intelligence + Titanium Precision" for Mianx.ai, an
> AI-native Business Operating System. Dark UI on midnight navy `#050914`;
> surfaces `#0A1222` and `#101A2D`; one primary hue, sapphire `#1677FF`, with
> `#319CFF` for accents and `#38C7FF` as a sparing signal colour; titanium
> `#C9D2DF` for secondary detail; text `#F5F8FC` and `#94A3B8`; 1px hairline
> borders `#22324A`. Gradients: bright
> `linear-gradient(135deg,#126BFF,#229DFF 55%,#38C7FF)` for gradient text and
> accents; deep `linear-gradient(135deg,#0B4FCC,#1163F0 55%,#126BFF)` for
> filled buttons with white text. 4px spacing unit, 10–12px control radii,
> 20–24px card radii. Enterprise-calm and engineered: no purple, no
> glassmorphism, no glow, no chrome text, no decorative animation, no more
> than one gradient focal point per screen. WCAG AA contrast required.

Tool-specific:

- **Stitch / v0** — request layout and structure, not a palette; they must
  consume the tokens above rather than invent colours. Treat their output as a
  proposal: reconcile every colour, radius, and spacing value against this
  document before any code is kept. Reject output that introduces a new hue, a
  new font family, or decorative motion.
- **Cursor** — read this document before editing anything visual. Use the
  `--mx-*` custom properties; never hardcode a hex value in a component. New
  visual work extends the token layer rather than adding one-off values, and
  any 3D or canvas work follows §9 without exception. Global palette changes
  are a reviewed decision, not a side effect of another task.
- **Figma** — mirror the `--mx-*` tokens as variables with these exact names so
  design and code share one vocabulary.

## Adoption status

Phase 1 introduced the token layer and applied it to the hero, the
static WebGL fallback, and the contrast-critical filled controls. The legacy
indigo/teal aliases in `app/globals.css` (`--primary`, `--accent`, and the
inline `rgba(99, 102, 241, …)` glows inherited from the approved HTML) are
still in place and are migrated in the redesign phase, not piecemeal. Until
then, new work uses `--mx-*` only.
